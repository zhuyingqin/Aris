# 模型选择旁显示 DeepSeek 相对价格：调研方案

初期调研日期：2026-10-19。以下保留当时的调查和方案；功能已于 2026-10-20 实施，最终计费口径、接口及验证见 [实现记录](model-price-ratios-2026-10-20.md)。

## 目标和验收口径

用户在选择模型之前即可比较价格：固定一款明确版本的 DeepSeek 为 1×，在聊天当前模型、模型菜单每个选项以及设置页的 Executor / Reviewer 模型选择旁显示参考倍率。倍率使用账号网关的实际计费配置，注明比较口径；缺价或无法比较时显示明确状态。

本阶段交付：查明模型数据链路、价格来源和访问条件，提出计算及展示方案，列出实施范围、待核实事项和验证要求。

## 已核实的现状

- `desktop/src-tauri/src/newapi.rs` 的 `downstream_models()` 从 `/v1/models` 获取可调用模型，`newapi_models()` 只返回模型 ID 并保存列表。
- `desktop/src-tauri/src/engine.rs` 的 `chat_model_options()` 同步返回模型 ID、标签和描述。`desktop/src/types.ts` 中的 `ChatModelOption` 没有价格字段。
- `desktop/src/chat/useChatRun.ts` 组装聊天选项；`desktop/src/chat/ChatComposer.tsx` 展示当前模型和按系列展开的菜单，`ChatComposerModel.css` 管理布局。
- `desktop/src/settings/ModelsSettings.tsx` 使用同一账号模型列表，但单独渲染 Executor / Reviewer 的原生下拉框。
- `crates/runtime/src/usage.rs` 的 `pricing_for_model()` 明确用于历史官方价粗略估算，DeepSeek V4 的 Flash / Pro 共用旧费率。它不能直接代表当前账号网关的扣费价格。
- 根据 `desktop/managed-newapi.json`，对配置网关的 `/api/pricing` 发起未登录 GET 请求，返回 `AUTH_UNAUTHORIZED`。该接口需要登录访问；本次未读取账号凭据，未核实登录后的响应结构或真实模型单价。
- 测试列表出现 `deepseek-v4.1-flash`，设置预设仍包含 `deepseek-v4-pro`。这些只证明代码中的型号，不证明当前账号可用型号。

## 推荐计算口径

基准必须是精确模型 ID，界面注明完整版本。可优先核实 `deepseek-v4.1-flash` 是否在当前账号的可调用列表且有有效价格；满足条件后固定为基准。其他 DeepSeek 型号也按各自真实价格比较。基准缺价或下线时显示“基准价格不可用”，避免静默换基准导致历史倍率含义变化。

输入和输出分别计算，价格须使用相同计费单位和相同账号分组下的有效费率：

```text
输入倍率 = 当前模型普通输入单价 / 基准模型普通输入单价
输出倍率 = 当前模型输出单价 / 基准模型输出单价
参考倍率 = (当前模型普通输入单价 + 当前模型输出单价)
         / (基准模型普通输入单价 + 基准模型输出单价)
```

建议模型旁的单个数字使用上述参考倍率，标为 `≈N×`；比较口径为同量输入与输出（1:1），普通输入不含缓存命中。它用于选择前比较，不是任意一次任务的实际费用倍率。悬停详情同时给出输入倍率、输出倍率、基准型号、更新时间和比较口径；网关提供缓存价格时补充缓存详情。

若已登录接口采用 New API 常见字段，则普通输入对应 `model_ratio`，输出对应 `model_ratio × completion_ratio`，并纳入适用分组倍率。这个映射须以实际响应及部署的计费规则核实后实现。同组通用倍率相同时会在比值中抵消，不能把账号 `groupRatio` 当作某款模型的价格。

按次 / 按张计费的模型不与 Token 费率相除；免费模型在明确确认免费后显示“免费”；缺价显示“价格未知”，零价或缺价的基准不能作除数。存在阶梯价格、特殊服务档位时，标明选用档位；无法确定有效费率时不生成误导性倍率。

## 推荐展示

- 聊天输入框当前模型：`模型名 · ≈N× · 思考强度`。基准模型显示 `1×`。
- 模型菜单：名称与倍率分列，倍率保持可见；顶部轻量说明具体的 `DeepSeek 版本 = 1×`，悬停显示计价细节。
- 设置页：Executor 和独立 Reviewer 的模型下拉选项均附带倍率，当前值旁也可查看说明；保持两种角色独立。
- 价格请求失败时，保留可用模型选择和已有价格缓存，显示更新时间 / 缓存状态；没有缓存时显示“价格暂不可用”。

以上 `N` 仅表示待实际价格计算的数值，本调研不提供未经核实的报价。

## 实施位置和数据流

1. 后端 `newapi.rs` 新增价格读取及规范化逻辑，复用 `authenticated_stored_session()` 和 `with_session()` 访问价格接口；仅向前端返回安全的价格元数据。
2. 新增独立的价格查询命令，在 `lib.rs` 注册，在 `api/tauri.ts` / `types.ts` 定义数据契约。保留 `chat_model_options()` 的现有同步调用方式，价格异步补齐。
3. 新建共用价格状态和格式化模块，聊天与设置页复用同一份规范化价格、基准、计算函数和说明文案。选择项提交时继续使用原始模型 ID。
4. 在登录后的价格首次加载、手动同步模型时刷新；设置合理 TTL，按网关、账号和分组隔离缓存，登出清理。可保存不含凭据的价格快照供离线使用，显式标记过期状态。下拉菜单展开和聊天流式更新不重复触发网络请求。
5. 在 `ChatComposer.tsx`、`ChatComposerModel.css` 和 `ModelsSettings.tsx` 接入标签。现有 `useChatRun.ts` 只复制名称等字段，若选择把价格附在选项上，需要一并保留新字段。
6. 文献阅读、定时任务、工作流等也复用了模型列表，后续可复用相同格式化模块。远程节点模型不得套用本机账号价格；需要远端提供相应价格元数据后才可比较。

## 实施前仍需核实

- 已登录 `/api/pricing` 的真实响应、当前账号可调用的 DeepSeek 版本、模型费率及计费类型。
- 分组费率、缓存、阶梯价格和特殊服务档位是否影响所显示的费率。
- 确定固定基准模型；本方案建议的单个参考倍率采用 1:1 输入输出口径。

## 实施后的验证

- 针对价格解析和倍率计算验证输入 / 输出费率不同、分组倍率、零价、缺价、未知计费类型及基准不可用。
- 针对共享缓存验证请求合并、失败保留数据、分组 / 账号切换隔离和登出清理。
- 聊天及设置页验证倍率、详情、选中值、原始模型 ID 提交、错误降级与中英文文案；检查窄窗口和长模型名布局。
- 运行受影响的 Rust 测试、相关 Vitest、TypeScript 检查和 `desktop/` 的 `npm run build`。本调研未运行构建或测试，因为尚未改动应用源码。
