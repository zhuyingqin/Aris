# SomniQ Studio 电脑操作落地路线

状态：实施建议，待独立审查。日期：2026-11-18。基线：`37b7818f`。
本文是 [Claude 的 Computer Use 设计稿](computer-use.md) 的配套规划，不替换原稿或当前项目目标。首个平台为 Windows Desktop。

## 目标与首发范围

让研究 Agent 在用户授权的范围内补齐专用工具够不到的界面步骤。首发任务是：用户在 SomniQ 专用的可见浏览器完成登录，Agent 下载指定论文到项目文献库，独立 Reviewer 根据来源和文件证据核验。网站未授权、登录未完成或论文身份不符时停下，不以“点过下载”声称完成。

Agent 也需要自己的对外身份。用户启用后，SomniQ 为项目开通专用邮箱，用它联系协作者、接收回复并继续原任务。支持开户的第三方服务可绑定到同一项目身份。邮箱功能可与可见浏览器开发并行，先交付邮件往来，再接入第三方账号。

现有分层保留：文件、文献、计算等专用工具优先，网页用浏览器结构化接口，原生应用先用 Windows UI Automation（UIA，控件树），最后才考虑截图坐标。专用工具失败不构成升级权限或切换渠道的理由。无人值守的研究任务继续走专用工具，不控制用户桌面。

## 对 Claude 方案的调整

1. **浏览器 M4 前置。** 有现成下载、快照和文献库通路，先验证登录交接及入库；桌面 M1 做小范围 UIA 探针。两条线共用授权与证据约定，不共用浏览器和桌面输入驱动。
2. **未知应用默认拒绝操作。** 不沿用“其他应用全操作”或“终端/IDE 可左击”。首版只对明确允许的应用、窗口及动作开放。在非交互任务、Reviewer、锁屏或授权不可用时拒绝；授权撤销、回合结束、用户接管后原租约和引用全部失效。
3. **限制替代执行入口。** 电脑操作会话在工具注册与调用入口都使用白名单，禁用无约束的 Shell、REPL、通用 Playwright 代码执行与非受控的 MCP、插件及委派入口；动态发现不得恢复这些权限。若现阶段封不住，仍可做本地测试夹具或手动选窗的受控原型，不对真实账号和用户桌面开放 Agent 试用。
4. **采集、保存、外发分开。** 用户从可信界面选定应用或窗口，授权前不把窗口标题和内容交给模型。首版只读授权单窗；禁止整屏和剪贴板。密码、系统安全界面、密码管理器、SomniQ 审批界面不得观测或操作；读不到可靠的遮蔽范围时不返回截图。审批显式展示屏幕或页面内容是否会发给所用 Executor 或 Reviewer 的模型服务；无法脱敏就停，不把原图或凭据落入日志。
5. **把 UIA 当主路线，视觉当补缺。** UIA 控件是否可读、是否支持直接动作、是否会抢焦点分别实测。WPS 自绘控件读不到就标记不支持，已授权时由视觉复核只读窗口，不能假定所有应用都能纯文本操作。Windows 助手独立进程、卡死隔离、过期引用、动作遇错即停、独占输入租约均保留。

## 分阶段交付

| 阶段 | 内容 | 过关条件 |
| --- | --- | --- |
| R0：基线与边界（Claude M0） | 3–5 个工作日验证：建本地仿出版商（登录交接、PDF 下载、表单预览）测试页和 Windows 临时文件夹；记录原版表现；探测记事本、资源管理器、Word/WPS 的 UIA 读取及可用动作；定授权、回收和跨工具阻断用例。 | 用同一任务定义和判定脚本可重复跑基线；明确哪些权限能在宿主硬拦、哪些尚做不到。独立审查通过后再开真实账号或桌面试用。 |
| R1：可见浏览器试用（M4 的下载子集） | 按任务创建 SomniQ 专用受控浏览器会话。授权到站点来源、会话及动作；相关登录和验证码由人接管，其间 Agent 不读、不点。暂不跨任务复用登录态；不向 Agent 暴露任意脚本执行。 | 先在本地测试站完成下载和回归，再由用户在授权的出版商站点实测一次；核对 DOI 或题名、PDF 可读性和项目入库记录。未授权的跨站跳转、新标签和权限升级在执行层拒绝或暂停等待用户。此阶段不开放真实投稿填表。 |
| R2：Windows 只读（M1） | 做最小 Windows 助手、单窗批准、控件树和受限截图、超时回收、证据报告。先支持记事本、资源管理器和测试用文档副本。 | 文本模型能读前两种应用；Word/WPS 实测只读检查批注和修订，并单独记录需视觉或不支持的版本。杀死助手，聊天收到明确错误，Desktop 保持响应，不自动恢复旧授权。 |
| R3：有限控件操作（M2） | 只对白名单控件开放选择、调用或设置值，不使用全局鼠标键盘。先做记事本保存到预置临时文件、资源管理器在临时目录创建文件夹；窗口选择、授权和拒绝原因在聊天可见。 | 执行前重验窗口、控件引用和授权；动作后用真实文件或目录状态判定；拒绝、撤销、双会话竞争、窗口切换、过期引用全部测过，无意外副作用。 |
| R4：按真实需求扩展（M3 与剩余 M4） | 根据 R2/R3 失败分类，仅对确实需要的任务试点截图定位、鼠标键盘接管，例如验收 MATLAB 图窗。投稿先做本地测试站的表单预览，真实站点需验证不会自动发送内容才评估开放。 | 混合 DPI 与遮挡下不会点错窗口；用户移动鼠标或急停后 1 秒内阻止新增投递，释放已按下的按键；无法确认结果的动作不重试。此处通过桌面操作触发的提交、发送、支付、删除、上传及同意条款由用户完成。 |

R0 + R1 的粗估为 2–3 周（按一名工程师、已有 Playwright 可复用、执行层阻断在 R0 验证可行）；不是发布承诺。R2–R4 等探针结果再排工期。对外 MCP、Claude 原生工具类型、模型执行代码、跨平台与 VM 不进首发（原 M5 后置）。

## Agent 自有邮箱与服务账号

项目的邮箱设置提供“创建 Agent 邮箱”。每个启用的项目默认有一个长期使用的收发地址，发件人标明研究助手身份。用户可以看到地址、已连接的服务、往来记录和自动化授权，也可以暂停处理、保留收件或断开连接。

SomniQ 已有邮箱适配层、收发界面、IMAP 来信监听和任务触发。实现时复用这些入口，补齐邮箱开户、项目级访问检查和来信恢复。现有通用邮件工具省略账户时可能选中已连接的邮箱。项目邮件工具由宿主根据任务绑定账户。宿主按项目保存邮箱绑定。新邮箱密钥和服务令牌放进 Windows 凭据存储，绑定记录保存凭据引用。开户凭据由宿主使用，日常收发凭据限定到单个邮箱和所需权限。Agent 通过受控连接器使用身份，模型只接收经授权的消息和操作结果。[邮箱适配层](../../desktop/src-tauri/src/mail/provider.rs#L30) · [账户选择](../../desktop/src-tauri/src/mail/agent_tools.rs#L318) · [来信触发](../../desktop/src-tauri/src/scheduled.rs#L1437) · [已有钥匙串实现](../../desktop/src-tauri/src/newapi/refresh_store.rs#L1)

### 邮箱开户和自主往来

1. **软件发起开户。** 首个提供方候选为 AgentMail。首次启用时，宿主通过提供方 API 开户并把返回的邮箱绑定到该项目。用户在设置中输入联系邮箱收到的一次性验证码，验证通过后即可对外发信。已接入提供方的用户可授权创建项目邮箱。同一组织内新建邮箱时复用持久的 `client_id`，首次开户恢复单独处理，因为重复调用注册接口可能轮换管理密钥。已有机构专用邮箱也可用现有收发连接接入同一工作流。[Agent 开户与验证](https://docs.agentmail.to/agent-onboarding) · [创建邮箱](https://docs.agentmail.to/api-reference/inboxes/create) · [密钥权限](https://docs.agentmail.to/permissions) · [重复请求](https://docs.agentmail.to/idempotency)
2. **一次授权后自行跟进。** 用户为任务选定发件邮箱、允许联系的地址、用途、有效期、发送次数和可外发材料。Agent 可以按授权主动发信、收信和跟进。比如授权联系指定作者索取复现代码，可允许首封邮件和同一会话中的一次跟进。实际发件人、收件人、抄送、密送及附件由后端在发送前校验，项目邮箱的聊天、定时任务及自动回复共用检查。新增收件人或超出允许的材料进入待确认，撤销授权后暂停剩余发送。首轮交付验收文本和公开文献引用。
3. **来信恢复原任务。** 发信后保存任务检查点，界面显示“等回信”，让其他工作继续。Desktop 运行时定期拉取来信，启动后根据保存的进度补拉退出期间收到的消息。宿主匹配项目邮箱、会话和已批准的往来地址，按提供方消息 ID 去重后恢复原任务。验证邮件交给开户流程，退信和自动回复更新任务状态。未匹配的邮件保留在收件箱。邮件文字和回复地址作为外部数据处理，跟进仍按原授权校验。独立 Reviewer 按需核对往来和最终产物的证据。[任务派发](../../desktop/src-tauri/src/scheduled.rs#L1466) · [提供方来信同步](https://docs.agentmail.to/knowledge-base/handling-inbound-emails)
4. **重启后能接着做。** 在调用提供方前持久化每次发送的操作标识和额度占用。收到确认时记录消息 ID。超时时按操作记录核对结果，在提供方的幂等时限内可用原键和原内容重试。超过时限仍无法确认时，任务显示“发送结果待确认”。新项目邮箱的运行进程按 [权限系统计划](permission-system-plan.md) 的作用域取凭据，日志保存发送和审查结果，用户可在任务页回看。[提供方发送幂等约定](https://docs.agentmail.to/idempotency#idempotent-sends)

### 第三方服务账号

- 用户指定服务并授权所需权限后，SomniQ 用项目邮箱通过官方开户接口、服务账号邀请或服务支持的 Agent 登录流程开通账号。服务允许自动开户且提供可验证的网页流程时，SomniQ 在项目专用浏览器内执行已授权的注册步骤。支持程序化邮箱验证的流程匹配本次开户、预期发件人、项目邮箱和失效时间，再校验验证链接的目标域名及跳转。验证码和登录链接仅在连接器的验证步骤中使用。遇到真人验证、身份材料、条款同意或付费时保存进度，用户接手后继续。[支持 AgentID 的服务接入示例](https://docs.agentmail.to/agentid-sign-in)
- 在项目内记录服务及账号 ID、授权范围、验证状态和凭据引用。后续任务在各自授权范围内复用。重复开户或超时时核对已有账号和完成状态。断开连接时停止使用，并按服务支持的能力撤销令牌或访问权限。项目登录态由该服务的连接配置单独管理，使用范围限定在对应项目和服务。

## 执行约定

- **授权与执行**：Desktop 宿主展示一次性批准，权限绑定项目、会话、目标和动作，默认不跨轮记住；按站点与按应用属不同授权。助手每次按实际目标校验。读、动作、接管真实输入互不继承。后续接 [权限系统规划](permission-system-plan.md) 的资源规则，不造第二套全局权限系统。
- **目标定位**：引用绑定助手实例、窗口和快照版本；窗口或页面变更后重新观察。像素动作额外绑定截图 ID 和坐标空间；焦点、遮挡、DPI 或显示器变化时拒绝旧坐标。先单步验证，只把互不改变目标的低风险操作合批。
- **动作和证据**：记录执行者、动作类型、目标、授权范围、结果与审查状态；不存表单输入和图像原始数据到日志。经许可的脱敏截图按附件保存，可清理。下载以落盘验证和文献入库为准；窗口检查记录应用版本和观察到的状态，不修改原稿或关闭编辑器。
- **审查**：Executor 操作并提交可核验证据；独立 Reviewer 只读必要证据，不获得浏览器会话、登录态或桌面租约。证据不足时回到 Executor 补证据或请用户接手。提交前停手由功能范围和操作白名单保证，不靠识别按钮文字。

## 验收与发布门槛

1. **安全先于成功率。** 未授权或拒绝、过期或撤销、跨项目会话污染、模型从页面读到指令、密码弹窗、向远端发送未授权图文、替代工具绕过、错误窗口和并发租约都要通过。检查真实结果（无输入投递、无不允许的文件或网络副作用、无凭据进入工具结果），不能只比对错误码。任何一项失败，相关能力保持关闭。
2. **分模型与任务比基线。** 至少测一种文本模型和一种视觉模型，固定初始状态和用户交接点，每个首发任务各跑 10 次；本地夹具以端到端至少 9/10 为试用门槛，真实站点单列。记录手动接手、错误分类、耗时、模型调用和用量。桌面失败按“树缺失、定位失效、权限暂停、动作已发但未验证”归类，再决定优化控件树还是加视觉。
3. **真实应用与工程检查并行。** 覆盖不同缩放、不同窗口、异常关闭及锁屏；前台输入另外做双屏和接管延迟实测。改共享 Rust 跑对应 crate 测试及 workspace 测试；改 Desktop 跑重点 Vitest 和 `npm run build`。试用以能力开关灰度，关闭后撤销租约、结束专用会话，并保留可回看的脱敏结果。

第一张实施工单：完成 R0 的两套测试夹具、当前版基线、UIA 观察探针和执行入口覆盖清单。先用探针回答“文本模型能看见什么、在哪里必须停、结果如何验证”，再确定可见浏览器的封闭试用范围。
