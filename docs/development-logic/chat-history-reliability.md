# Chat 历史中 PDF 取证、主线授权与工具恢复的修复

## PDF 读取

本地 `read_file/read_files` 和网页 `WebFetch` 共用 runtime 的 PDF 提取入口，使用与桌面论文库同版本的 `pdf-extract/lopdf`，按页解析字体、编码、对象和文本。旧的流扫描器只用于主解析失败后的尽力读取。

本地工具结果在分页内容之外提供 `pdfExtraction`：提取方法、`readable/unconfirmed/no_text` 质量状态、总页数、没有可读文字的页、警告，以及始终为 false 的 `exactContentVerified`。分页不会移除质量信息，也不因添加提示改变原文本行号。字符映射异常、页面解析失败、缺少文字的页面和超过 1,000 页的截断，都不能成为可靠全文取证。

简化解析器的降级结果必须为 `unconfirmed`。网页降级内容内也保留提示，返回 `status=incomplete` 和 `pdf_text_quality_unconfirmed`。旧 `pdf_text` 快照可以留存追溯，但不能用旧游标继续取证；错误指导重新请求原 URL。新快照使用 `pdf_text_v2`，HTML 等其他快照保持原行为。

检索层也执行质量检查：旧解码器、缺少文本层或质量未确认的结果不会建立验证证据引用，也不会把其 Markdown 快照登记成可继续取证的来源；对已知候选路径的本地读取同样尊重质量标记。候选书目信息可以保留，不能据此增加直接取证计数。

`readable` 表示文本层可读，不证明公式布局、字符身份和原页完全一致。精确引用、公式和数值核验仍需要渲染原页。扫描页引导使用本地页面查看/OCR；这次修复没有为 Chat 新增自动 OCR 执行器。

## 项目主线

最新明确用户请求就是当前任务的授权，包含保存主线之外的任务。保存的意图、主线和里程碑提供背景，不能替换、缩短或阻断新请求。提示中显示活动总结的实际 reviewedAt；缺少总结和旧的偏离提醒，都不单独触发再次确认。

主动支线仍须服务当前任务及验收条件。未经请求、无助于当前任务的扩展应暂缓；只有必要的歧义、冲突或扩展才需要询问。短期任务不会自动重写长期项目意图。

## 工具恢复

共享 ConversationRuntime 在工具结果进入模型上下文前识别五种已知失败：正则转义、嵌套引号、缺失路径、失效编辑锚点和脚本类型错误。第一次失败就保留原诊断并给出具体替代方法：发现实际路径、读取当前原文和 revision、使用字面量 edit_file/multi_edit，或保存独立脚本后执行。

同一机制再次出现同类错误时，结果包含 `toolRecovery.changeMechanismRequired=true`。完全相同的失败请求只允许实际执行两次；改描述、超时或后台标记不能绕过。第三次返回可见错误，其他读取、发现、纠正调用继续开放。修改后的请求仍可执行；成功的结构化修改清除旧命令的失败记录，让修复后的验证命令可重新执行。

恢复状态属于一次用户任务，压缩上下文不清空，下一次明确用户输入会重置。成功读取不会误判为脚本错误；未识别的网络/超时等暂时失败不使用这项确定性错误的重试限制。该限制不阻止所有不同命令的变体：它提供机制切换信号，并确定性地阻止未经纠正的同一请求循环。

## 验证

回归覆盖自定义 Type 1 字体下数字编码、损坏 PDF 降级、混合文字/扫描页、分页质量信息、多语言数学文本、WebFetch 完整性及旧快照处理；授权规则覆盖缺失主线和带偏离记录的主线；恢复覆盖五类诊断、不同命令变体的机制提示、未改变请求的重试上限、纠正后验证以及成功内容/暂时错误的负例。

2026-10-08 验证结果：

- `cargo test --workspace --offline -j2`：1,343 项通过、0 失败、5 项忽略。
- `cargo test -p tools --offline web_fetch`：17 项通过；`cargo test -p runtime --offline retrieval_guard`：47 项通过。
- Desktop 的 3 个 Chat 测试文件：72 项通过；`npm run build` 通过。
- `cargo check --manifest-path desktop/src-tauri/Cargo.toml --offline -j2` 通过。
- `git diff --check` 通过。

使用最近历史中的原始 PDF 另做本地提取复核：43 页全部提取到文字，旧的乱码标题消失，卷号 18 和年份 2017 正确恢复。`exactContentVerified` 仍为 false，不能由此声称全部公式已经核对。结果和测试日志保存到 `.somniq/diagnostics`，本次验证索引为 `chat-reliability-verification-20261008.md`。

该检查不调用远端模型，不能验证模型实际遵循提示的程度。上述结果验证工作区源码；本次没有重新打包或更新桌面安装版，安装版须重新构建后才会包含这些修复。
