# Go / Plus / Pro 会员实施记录

日期：2026-09-23。接续[会员方案](site-membership-model-access-plan.md)。
本次实现位于 `codex/somniq-identity`，保留已推送的 `0.4.72` 基线；未部署生产或修改生产数据。

## 已交付

- Go ¥29/月、Plus ¥49/月、Pro ¥99/月：金额由账号服务统一提供，原价格页、控制台会员页和管理员读取同一契约。
- 沿用原有 UI：主页保留原结构；账号入口复用原控制台顶栏、侧栏、卡片与明暗主题，会员管理作为管理员侧栏入口。价格页保留原左右布局和下方对比表，仅替换套餐数据。
- `/admin.html`：配置每档精确模型名单、默认执行模型、默认独立审查模型及启用状态；支持从 New API 读取模型，或手动填写已配置的模型 ID。
- 用户会员：搜索用户、开通、切换档位、设定到期时间、撤销会员；保存变更原因和前后快照。并发编辑以版本号防止覆盖。
- 账户中心：`/dashboard.html` 与 `/account.html` 使用同一控制台，显示当前会员、有效期、可用模型、默认模型与原有算力余额，管理员可从侧栏进入管理页。
- 服务端授权：每次模型调用检查当前会员和精确模型；到期、禁用套餐、降级、撤销立即影响后续请求。前端状态和客户端提交的档位不参与授权。
- New API 适配器：使用各用户专用 Key，同步并读回核验模型白名单；同步失败时阻止新策略下的调用。持久化队列负责重试和周期核验。

SomniQ 保存身份和会员策略，New API 保持官方源码及原有渠道、用量、钱包职责。无需维护 New API 代码分叉；仍需正确配置 OIDC、模型渠道与用户分组。
模型发现读取管理员自己算力账号的可用模型，不代表全局模型库存或渠道健康检查。模型名由运营配置，测试里的模型不是生产预设。

## 配置与使用

完整环境变量、启动命令和 API 见[账号服务 README](../../site/account-server/README.md)。

1. 在已配置的身份服务中查出管理员的固定 OIDC `sub`，写入账号服务的 `SOMNIQ_ACCOUNT_ADMIN_SUBJECTS`，重启服务。多个 subject 用逗号分隔。服务端同时核对 issuer；邮箱、用户名、New API 管理员角色不能替代此授权。
2. 以 `VITE_ACCOUNT_MODE=independent` 构建 Site，配置账号服务及同源转发；新增路由见 [Nginx 示例](../../site/account-server/deploy/nginx.preview.conf.example)。初始套餐未启用、模型为空，现有预览账号也不会自动取得付费会员。
3. 登录 `/account.html`，接受协议并连接算力。进入 `/admin.html`，配置三档模型与两个角色的默认选择，启用并保存。
4. 在“用户会员”中选择用户、档位、有效期并填写原因。用户的新请求依据当前权益执行；已获许可且正在返回的有限时长响应可结束。
5. 失败的上游同步会在用户列表显示重试入口；账号服务重启后继续处理队列。New API 的服务 Key 不应被手工改成有限 Key 额度；用户钱包仍负责用量扣减。

会员管理目前是人工授予。月价是报价，不会产生付款记录、自动扣款、自动续费或周期算力赠送。
已开通会员仍需要 New API 账号可用且有算力余额；此实现不更改已有钱包余额和路由倍率。

## 后续上线范围

当前仍是独立账号模式；默认 Site、原有 Desktop/PWA 和旧 New API Key 继续使用旧契约。完整生产切换还需部署身份服务、SMTP 与品牌注册、旧账号绑定、设备会话及旧 Key 迁移，并收紧旧上游入口。浏览器 Cookie 不能直接用于桌面或 SDK Bearer 登录。

账号库使用 SQLite/WAL 和单进程权限锁，暂不支持多副本。生产需完成备份恢复、账号库方案与已有数据库迁移演练。新增表在账号服务启动时初始化，不写 New API 数据库表。

后续收费阶段接入支付订单、回调验签、幂等开通、退款与续费；在此之前由管理员根据实际业务开通。上游 GitHub 兼容检查已纳入会员用例，继续先验证候选版本再评审升级，未开启自动生产部署。
