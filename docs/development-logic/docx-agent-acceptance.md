## 判断依据和边界

评价器独立检查原件哈希、真实读取记录、最终原生结构、文字、实际 PDF、schema 和业务条件。`agentRenderedFinalRevision` 必须来自模型自己的生产工具调用，评价器的二次渲染不能替代。两个后台衍生任务分别核对零文件写入和两轮指令后 7 人、执行 5 人、零表格、不残留 8 人。REQ-08 的原任务还包含四份材料合并和跨岗位共享人员去重，本样本没有验证这两项，不能记为完整客户任务通过。

自动结果仅覆盖逐项列出的断言。多轮模型最终答复的解释性段落计数仍有内部矛盾（“8 个段落”附列“1 个标题 + 6 个正文段 + 2 个脚注占位”）；文件人数与零表格条件通过不能证明所有说明性陈述都准确，该问题保留为后续 Agent 改进项。

本次开发验收的 Codex 对全部 13 页给出单独观察，逐页直接查看或以 SHA-256 确认与已查看的原生验收图片完全一致。 这是本次开发验收的观察，不是被测软件模型的视觉检查。登记表标题已有字形缺陷仍按 [办公报告](docx-office-acceptance.md) 保留，不能宣称任意页面均无缺陷。独立 Reviewer 未运行，生产证据的 pending/unverified 状态没有提升为通过。

本测试仅允许本地文件、文档和审计工具执行。Shell 在产品 workspace-write 权限下仍要求额外授权，本程序没有自动批准；因此文件处理自动通过不等于任意 Shell 工作流通过。`tool-calls.json` 记录已执行调用，完整 `session.events.jsonl` 另记录被权限拒绝的尝试，机器报告分别统计两者。首个报价任务尝试将 PDF 直接交给 `ReadMediaFile` 被拒绝，随后如实说明未做视觉确认；PDF 文字提取与渲染元数据不能代替查看页图。

首轮工作目录位于研发仓库忽略的 `.somniq` 中，搜索返回空且产品提示词继承了无关 diff。该轮已中止并保留诊断，不纳入结果。当前模型工作目录在 Git 仓库外的独立临时目录中；复现时同样应避开研发仓库的忽略路径。

旧版多轮验收把完整两轮请求预先写入可读的 request.json，模型提前看到七人要求，导致第一轮就跳过八人表格。即使旧脚本最终断言为 automated_pass，该项也已作废，不计入这里的完成数。新版记录位于模型工作目录之外，未呈现指令不会提前写盘，工作目录采用中性编号；每轮完成后保存 DOCX 实物，另要求第一轮确为八人原生表格，第二轮才是七人、执行五人、零表格。九个单轮用例与重测多轮用例的 harness 版本和原始哈希分开保留；生产工具、提示词与共享 Chat 代码相同。

本地原始运行位置见 `.somniq/research/docx-office-repair-20261111/agent-run-2-location.json`；开发验收审计、最终页图观察和保留快照位于同一证据目录。详细运行/源码/文件哈希及失败条件见 [机器报告](docx-agent-acceptance.json)。复现命令见 [工具说明](../../tools/docx/README.md)。本批没有桌面 UI、Word/WPS 或旧二进制 `.doc` 验收，也没有新安装包发布。
