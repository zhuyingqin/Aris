# LaTeX PDF 文字拖选修复

本次目标是修复 PDF 正文、行尾空白和公式附近无法连续拖选的问题，并保证松开鼠标后选区可复制，拖选不会触发链接或源码跳转。仓库现有 `.somniq/project-goal.json` 记录另一项任务，保留原状；本次目标和浏览器截图保存在 `.somniq/changes/pdf-selection-2026-10-27/`。

## 原因

- 阅读文字层只允许单个文字 span 接收鼠标操作，span 之间的空白落到覆盖整页的源码跳转按钮。按钮会接收焦点并阻止文字选择。
- PDF 文字项目采用绝对定位。在行尾或行间直接使用浏览器默认的光标定位，选区起点可能落到不相干的 DOM 项目，拖选范围与鼠标位置不符。
- PDF.js 单独输出的空格和空字符串换行项目曾被过滤，复制时可能连接相邻单词或丢失换行。
- 预览只在按住鼠标时保护已渲染页面。跨页选择完成后收缩渲染窗口，会卸载选区起点所在的页面。

## 修改

`PdfPage.tsx` 的阅读文字层接收整页鼠标操作。源码和链接按钮继续提供键盘入口，鼠标链接由页面坐标命中测试处理；已经发生拖动或存在文字选区时不跟随链接。

`pdfTextSelection.ts` 保存浏览器的真实 `Selection`，用最近的 PDF 文字项目和浏览器字符边界查询定位端点。它支持向前、向后和跨页拖选、重新拖选已选中文字、Shift 扩展以及预览边缘自动滚动。双击继续使用原有的 SyncTeX 逆向搜索。文字项目的水平缩放和页面缩放通过实际 DOM 几何反映在选择坐标中。

`pdfGeometry.ts` 保留空格，并将空换行项目附加到前一个文字项目。幻灯片对象编辑模式跳过没有可编辑文字的项目。

`TypesetPdfPreview.tsx` 在虚拟化时保护当前选区覆盖的页面；清除选区后恢复正常的渲染窗口。PDF 换行元素采用绝对定位，避免生成参与普通排版的隐形行框。

- `node node_modules/typescript/bin/tsc --noEmit` 通过。

- 在本机浏览器中使用实际编译的两页 LaTeX 示例验证。恢复旧的透明按钮命中样式后，从行尾空白开始拖动得到空选区；修复后，相同操作选中了下一行的正确文本。
- 在 75%、125%、200% 缩放下验证选择；125% 下跨过两处行间公式后选区保留，75% 下从第一页拖至第二页，选区端点仍分别位于两页，边缘自动滚动正常。
- 从 PDF 链接文字开始拖动可选择文本且不跳转，单击仍跟随链接；双击正文仍请求源码定位。PDF 滚动容器保有键盘焦点。
