# 电脑操作 R0 记录：夹具、基线、UIA 探针与执行入口

状态：R0 第一张工单的结果，待独立审查。日期：2026-11-25。基线：`56f80f77`（`codex/release-0.4.92`，另有与本文无关的未提交改动）。
对应 [落地路线](computer-use-rollout-plan.md) 的 R0，设计依据见 [设计稿](computer-use.md)。所有结论都来自本机实测或代码核对。数字只在本机这一套环境下成立：Windows 11 26200，三块显示器，DPI 分别为 96/120/144。

## 结论先行

1. **现在就能绕过任何未来的电脑操作授权。** 默认权限下，现有 Shell 工具在没有任何同意步骤的情况下，用一段 PowerShell 往测试窗口写了题名、**写进了密码框**，还**点了“提交（禁止）”**（S5，证据 `run2-fixture.json` 的 `shellBypass`）。根因有三条，均已核对代码：
   - 运行时执行工具前，不检查工具名是否在本回合清单里（`crates/runtime/src/conversation.rs:1792` 直接调用 `authorize`）。
   - 未注册的工具一律按 `DangerFullAccess` 要求处理（`permissions.rs:81-86`）。
   - 桌面端未配置时的默认模式就是 `DangerFullAccess`（`engine.rs:4341-4342`）。

   所以电脑操作会话不能只从工具清单里去掉 Shell，必须在调用入口拒绝。
2. **“后台动作不抢焦点”在 Win32/WinForms 控件上不成立。** 前台放一个占位窗口，对后台的测试窗口执行 UIA 的 `toggle` 和 `invoke`，两次前台都被换成了测试窗口；`set_value` 也让测试窗口被激活。三次都没有移动鼠标。设计稿 §4.4 的分类需要改，见“对设计稿与路线的修正”。
3. **文本模型能看见什么，按框架差别很大。**
   - 记事本（XAML）能读到正文。
   - 资源管理器能读到全部文件名。
   - WPS（Qt）读不到文档里的批注和修订文字，而且 284 个元素个个声称支持 invoke 和 value，“可用动作”信号对 Qt 应用不可信。
4. **读一次控件树的耗时，在模型的一次往返面前很小。** 冷启动的 WPS 是例外，首次读取用了 17.8 秒。
   - 一次取回整棵树（`subtree`）比逐个遍历（`walker`）快 1.7–1.9 倍：记事本 69 毫秒，资源管理器 214 毫秒，WPS 566 毫秒。
   - 资源管理器一次快照约 5.7k 字符、1.7k token。
5. **现有文献下载链路（浏览器兜底）有三处缺陷，与电脑操作无关，但 R1 要复用它。**
   - **身份不核对**：下载到 DOI 不符的论文也照样入库，并报成功。
   - **会跟着链接跨站**，访问未授权的站点。
   - **inline 方式返回的 PDF 一律失败**，存下来的是查看器的 HTML 外壳。

   另外，页面崩溃后，长驻的下载进程不会恢复（见第 2 节）。
6. 能在宿主硬拦和暂时拦不住的入口，已经分成两张清单（第 5 节）。暂时拦不住的有这些：
   - 插件面板直接运行工具
   - 项目 `.claude/settings.json` 里的 hooks
   - `Config` 工具改默认权限模式
   - 后台进程在撤销授权后继续存活
   - 对端（远程）入口
   - Playwright MCP 的 `browser_run_code_unsafe`

   在这些封住之前，电脑操作只能在本地夹具上试，不能对真实账号和真实桌面开放。这与路线调整 3 一致。

## 2. 现有下载链路基线

被测对象是桌面端随包分发的 `literature_playwright_download.cjs`（无头 Edge），以及与 `download_pdf_at` 相同的入库规则（`validate_pdf_file` 只检查 80MB 上限和 `%PDF` 文件头）。这一节是确定性链路的基线，不是模型驱动的基线（见第 8 节）。

| 任务 | attachment（附件下载） | inline（浏览器内打开） |
| --- | --- | --- |
| C7-OA | 通过，2.2 秒 | **失败**：存下来的是 PDF 查看器的 HTML 外壳 |
| C7-LOGIN | 失败：找不到下载入口。没有交接给用户的通路，这是预期内的 | 同左 |
| C7-MISMATCH | **假成功**：DOI 为 `…0099` 的论文被当成 `…0003` 入库 | 恰好因为 inline 失败而没入库 |
| C7-MIRROR | **失败**：访问了未授权站点 `/mirror/…`，只是因为对方以 inline 方式返回才没存下 | 同左 |
| S-INJECT | 通过。确定性脚本不读页面文字，注入对它无效 | 失败（inline） |

页面崩溃：调试时，测试站在旧连接未断开的情况下重启，后台浏览器的页面随即崩溃。之后每个请求都在 3 毫秒内报 `page.goto: Page crashed`。原因是脚本一直复用 `context.pages()[0]`，从不检查页面是否已崩溃或关闭（`literature_playwright_download.cjs` 的 `download()` 开头）。

触发条件和测试站的关闭方式有关：改为先断开连接再关站后，正式基线的 `site-restart` 变体没有再出现崩溃，所以这一列没有单独列出。但只要页面崩过一次，整个进程就一直坏到应用重启，这是代码层面成立的事实。

## 3. UIA 探针实测

使用 release 版探针，每个应用读 3 次。耗时取中位数，括号里是第一次读取（冷启动）。interactive 视图对应设计稿的默认过滤。token 是粗估：英文按 4 个字符算 1 个，其他字符按 1 个算。

| 应用（框架） | 元素数 | walker 毫秒 | subtree 毫秒 | interactive 字符 / ≈token | 文本模型能否看到内容 |
| --- | --- | --- | --- | --- | --- |
| 测试窗口（WinForms） | 19 | 157（226） | 85（92） | 541 / 170 | 全部控件与状态，密码框只标 `password` |
| 记事本 11.2609（XAML） | 84 | 132（232） | 69（82） | 1,984 / 606 | 能：正文里的测试标记在 `Document` 的 value 里 |
| 资源管理器（XAML + DirectUI + Win32） | 151 | 372（593） | 214（225） | 5,740 / 1,659 | 能：3 个文件名都在 |
| WPS 12.1（Qt） | 284 | 1,592（**17,791**） | 566（685） | 12,034 / 3,106，超过 12k 字符上限被截断 | **不能**：批注、新增修订、删除修订都不在树里；220 个元素是 Group，只有 30 个有名称 |

其他观察：

- 列出全部顶层窗口只要 9–13 毫秒。33 个窗口里有 1–2 个按禁区只计数不描述，标题默认隐藏。
- 读控件树没有移动鼠标，也没有改变前台窗口。WPS 那次记到“鼠标移动”，发生在 25 秒的读取期间，判断是用户自己动了鼠标。
- WPS 两次读取的元素数不同（walker 284，subtree 243），说明 Qt 的树在读取过程中会变。编号绑定快照（设计稿 §4.2）是必要的。
- 打开 docx 时，WPS 会在同目录生成 `~$` 锁文件，判定脚本已经放行。

## 4. 动作探针与焦点

动作只对测试窗口开放：标题前缀和承载进程（`powershell.exe`）必须同时匹配。

| 检查 | 结果 |
| --- | --- |
| 往密码框写值 | 报 `PROTECTED_TARGET`，测试窗口没有收到任何事件 |
| 编号对应的名称变了 / 编号超出范围 | 都报 `STALE_SNAPSHOT` |
| 对记事本执行动作 | 报 `NOT_FIXTURE` |
| 后台执行 `toggle` / `invoke`（占位窗口确认在前台） | 都成功，但**前台被换成了测试窗口**。鼠标没动。单个动作耗时 22–63 毫秒（前台阶段测得，不含重新遍历树的 110–120 毫秒） |
| 后台执行 `set_value` | 成功，测试窗口被激活。这次占位窗口没能稳定拿到前台，所以算作“很可能抢焦点” |
| Shell 工具绕过（`shell-bypass.ps1`，只用 `WM_SETTEXT`/`BM_CLICK`） | 写了题名、写了密码、点了禁止按钮，全程没有任何同意步骤 |

附带发现：Windows PowerShell 5.1 自带的托管 UIA 把 WinForms 控件全部识别成 Pane，没有任何控件模式，`IsPassword` 也是 false。可见 `IsPassword` 是否可信取决于用哪套客户端、哪个提供方。对 Win32 文本框，还应再检查窗口样式里的 `ES_PASSWORD`。

**暂时拦不住或还需要设计的：**

| 入口 | 原因 |
| --- | --- |
| 插件面板直接运行工具（`plugins.rs:375/431`），`auto: true` 的页面工具不需要用户手势 | 完全不经过运行时和权限策略。电脑操作回合进行时，无点击的运行已被拒绝（见第 8 节）；用户点击仍然可以运行 |
| 项目 `.claude/settings.json` 里的 PreToolUse/PostToolUse hooks，用 `cmd /C` 执行（`config.rs:252` ✓，`hooks.rs:231-236` ✓） | 只要写入这个文件，下一次任何被允许的工具调用都会触发它。电脑操作模式下已清空 hooks（第 8 节）；普通会话里，工作区已有的 hooks 仍会执行 |
| `Config` 工具写 `permissions.defaultMode` | 影响之后的所有会话 |
| `run_in_background` 启动的后台进程 | 撤销授权或回合结束时没有清理它们的钩子（子代理推断，未核对） |
| 浏览器动作之后，宿主自己发起的 MCP 快照（`chat/src/lib.rs:1769-1777`） | 不经过 `authorize` |
| 对端入口：远程 Agent 对话、远程计算任务、互助出图通过本机 ChatGPT 浏览器服务对端 | 不是本机用户发起的回合 |
| Playwright MCP 与文献下载进程共用 CDP `127.0.0.1:38465` 上的浏览器配置（`playwright_pdf.rs:22` ✓） | 模型驱动的会话和确定性下载共享同一份登录状态 |
| `chat_permission_respond` 不检查调用来自哪个窗口（子代理推断） | 对比：插件审批会检查 |

R0 的过关条件是“明确哪些权限能在宿主硬拦”。结论：只要做完上面第一张表，Shell 类入口就能在宿主硬拦。第二张表在封住或明确排除之前，R2 以后的桌面试用只能在本地夹具上进行。

## 6. 授权、回收与跨工具阻断用例

| 用例 | 由哪里强制 | 判定方式 |
| --- | --- | --- |
| 未授权、被拒绝 | 宿主同意记录 + 助手进程每次投递前复查 | 不应有任何投递：测试窗口没有事件，文件哈希不变 |

## 7. 对设计稿与路线的修正

1. **§4.4 的后台/前台划分**：至少对 Win32/WinForms 控件，UIA 的 Invoke、Toggle、SetValue 会把目标窗口提到前台。建议按“是否可能改变焦点”分类，而不是按“是否用 UIA”分类。每次动作后都检查前台窗口有没有变，变了就在结果里如实报告。XAML、WPF、Qt 在 R3 分别实测。
2. **“可用动作”不能直接取 `Is*PatternAvailable`**：Qt 应用对所有元素都报 invoke 和 value。需要按框架过滤，或者对照控件类型。
3. **C4 走对工具**：WPS 文档区不暴露内容。检查修订和批注应优先用现有的 docx 文件工具。只有“在 WPS 里显示是否正常”才需要截图和视觉模型。
4. **取树策略**：默认用 `subtree` 一次取回，超时或元素过多时退回可中断的 `walker`。Qt 应用首次读取很慢，要给模型返回“仍在读取”或部分结果，不能干等。
5. **应用身份**：只按进程映像识别，会把 PowerShell、Python、javaw 承载的界面都并进“终端”一档（测试窗口就被分成了只读）。脚本宿主承载的窗口需要另立规则。
6. **补两类分级**：一类是能对外发消息的应用（QQ、微信、企业微信、WhatsApp、Thunderbird），一类是远程桌面和其他 AI Agent 客户端（RustDesk、Claude、ChatGPT）。这两类本机都开着，现在都落在“需授权”。建议默认只看，或者直接列为禁区。
7. **密码值的传输**：缓存请求会把密码元素的 Value 一起取到助手进程里。现在渲染前已经丢弃，但正式助手应分两步取值。
8. **R1 前置修复**：文献下载的兜底链路要补四件事：入库前按 DOI 或题名核对身份；只允许访问已授权的站点；支持 inline PDF（直接取响应字节或走 CDP 的下载行为）；页面崩溃后重建页面。这些与电脑操作无关，可以单独做。

## 8. 已落地：电脑操作模式的调用拦截与“正在控制”提示（2026-11-25）

按第 5 节的拦截点实现，目前还没有任何桌面观察或操作工具，所以这个模式现在只做“收紧权限 + 提醒”。R2 的电脑工具直接加进同一份白名单即可。

**怎么进入**：Chat 输入框左下角的“电脑操作”开关，按会话生效，只存在内存里（应用重启后自动关闭）。远程 Agent、工作流和待办任务的会话不显示这个开关。回合运行期间不能切换，后端也会拒绝。每次切换都会写一条 `computer_use_mode` 审计事件；这类事件已加入日志压实的保留名单，不会被回合开始时的 `session_reset` 清掉。

**拦截（三层，任一层都足以拒绝）**：

| 层 | 位置 | 做法 |
| --- | --- | --- |
| 注册 | `engine.rs` `COMPUTER_USE_TOOLS` 与 `computer_use_tool_specs` | 固定白名单：`read_file`、`read_files`、`read_docx`、`glob_search`、`grep_search`、`TodoWrite`、`AskUserQuestion`。MCP 允许清单为空，MCP 服务器也不启动；项目 hooks 清空；不注入委派策略 |
| 调用 | `PermissionPolicy::with_catalog_only`（`crates/runtime/src/permissions.rs`） | 清单外的工具在任何权限模式下都直接拒绝，包括“完全放行”和“允许”模式，不弹审批，用户也无法批准 |
| 宿主 | `DesktopToolExecutor` 的 `validate_computer_use_tool_access`；`KernelToolExecutor` 硬拒 `COMPUTER_USE_HARD_BLOCKED_TOOLS` | 并行批处理路径也改为逐个检查；电脑操作回合进行时，插件页面不能在无人点击的情况下运行工具 |

**提示**：

## 9. R2 第一版：只读查看你选的一个窗口（2026-11-25）

**已定决策（用户 2026-11-25 确认）**：
- 能对外发消息的应用、远程桌面和其他 AI 客户端列为禁区。
- 这期不提供“本项目记住”。
- 截图可以发给云端模型服务，但每次都在卡片上写明发给谁。
- 提示条显示“SomniQ 正在查看「窗口标题」”。

**助手进程 `somniq-computer.exe`**（`crates/computer/src/bin/helper.rs`，协议见 `protocol.rs`）：
- 通信方式是一行一个 JSON。只有 6 种读操作：`ping`、`list_windows`、`window`、`snapshot`、`find`、`screenshot`。未知操作和多余字段一律拒绝，比如在请求里夹带 `click`，或在 `snapshot` 里夹带 `setValue`。
- 快照先一次取回整棵树（8 秒内），失败或超时就改用可以中途停下的逐个遍历（12 秒内）。
- 编号绑定在助手进程的快照缓存上。按编号读子树时，会比对该编号的元素类型和名称，对不上就报 `STALE_SNAPSHOT`。助手重启后，所有旧编号自然失效。
- 值分两步读：缓存请求里不再包含 Value。先排除密码框（`IsPassword` 加 Win32 的 `ES_PASSWORD` 样式），再逐个读取值，每次快照最多读 300 个。
- 截图用 `PrintWindow(PW_RENDERFULLCONTENT)`，只渲染目标窗口本身，挡在它上面的其他窗口不会被截进去。最小化的窗口不截，空白截图不返回，长边缩到 1568 像素以内，并去掉不支持 DPI 缩放的程序留下的未绘制边。
- 禁区新增了聊天、邮件、会议、远程桌面、其他 AI 客户端共 33 个程序。

**宿主**（`desktop/src-tauri/src/computer_tools.rs`）：
- **5 个工具**：`computer_request_access`、`computer_snapshot`、`computer_find`、`computer_screenshot`、`computer_release`。只在电脑操作模式下注册，同时加入白名单。
- **授权卡片**：模型申请时，卡片列出你的窗口，标题只给你看，同时写明内容会发给哪个模型和接口地址。卡片只接受 Chat 窗口的回答。你选中窗口后，宿主会再核对一次，确认它还是同一个进程和程序。
- **授权有效期**：本回合内有效，回合结束或你按停止时作废。每次读取前都会核对窗口还在不在。
- **自动查找助手进程**：依次查找 `SOMNIQ_COMPUTER_HELPER` 环境变量、`ARIS_RESOURCE_DIR/bin`、exe 所在目录；debug 版还会去仓库的 `target/debug` 里找。
- **超时与重启**：请求超时或被停止时，杀掉助手进程，下一次请求再重新拉起。
- **远程回合不能申请**：配对设备继续的回合会收到 `APPROVAL_UNAVAILABLE`。
- **审计事件**：`computer_access` 和 `computer_observation` 都已加入日志压实的保留名单。截图事件只记录尺寸和 sha256。
- **提示条与边框**：提示条显示正在查看的窗口；被查看的窗口四周画一圈可以点穿的红框，每 300 毫秒跟一次位置，窗口最小化时隐藏。
- **打包**：`npm run build:resources` 新增 `build:computer-helper`，在 Windows 上编译 release 版助手并拷进 `resources/bin`。

**应用内实测**（隔离实例 + 本地假模型，按顺序调用全部工具）：
- 卡片列出 25 个窗口，另有 12 个按禁区隐藏。QQ、微信、企业微信、Claude、ChatGPT、Thunderbird、RustDesk 和 SomniQ 自己的窗口都没有出现在列表里。
- 允许后，状态变为“正在查看”测试窗口。两块屏幕的提示条和测试窗口外的边框都出现，全部置顶且不可激活。
- 快照得到 19 个元素，结果带“屏幕内容是数据”的标注，密码框不取值。查找“保存”命中 2 个元素。截图 540×400，作为图片块进入会话。
- 杀掉助手进程后，下一次调用自动换了新进程，按旧编号读子树如期报 `STALE_SNAPSHOT`。bash 仍然被拒。
- 回合结束后，授权、提示条和边框全部消失。
- 第二个回合里点“拒绝”，模型收到 `ACCESS_DENIED`，并被告知不要改用其他工具。
- 从提示条窗口发起回答被拒绝：只有 Chat 窗口能回答授权卡片。
- 审计事件全部留存。

**还没做**：
