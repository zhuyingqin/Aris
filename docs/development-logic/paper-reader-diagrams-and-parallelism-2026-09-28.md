# 论文讲解：讲解图与并行生成

## 问题

1. 讲解全是文字。方法流程、模块关系和实验对比这类内容，读者需要自己在脑中画图。
2. 生成很慢。逐页识别、每个主题的初稿、独立审核、修订和复核全部串行，一篇 6 个主题的论文最多要依次等待约 24 次模型请求。

## 讲解图

每个主题新增一张图（`GuideLesson.diagram`），导读新增一张论文全景图（`GuideOutline.diagram`）。字段可选，旧讲解照常可读，协议版本不变。

**图是数据，不是标记。** 模型只能输出两种 JSON，Rust 校验通过后才保存，前端负责绘制：

| 类型 | 用途 | 校验（`diagram_problem`） |
| --- | --- | --- |
| `flow` | 流程、结构、数据流、推导链、因果关系 | 2–14 个节点，id 为唯一的 ASCII 字母、数字或下划线；标签非空且不超过 80 字；1–24 条边，两端都必须存在；最多 4 个分组，每个节点最多属于一个分组；不允许多余字段（比如样式） |
| `bars` | 实验主题中同一指标的数字对比 | 2–12 条，数值有限；必须标明 `origin`：`paper`（来自原文表格）或 `teaching`（教学构造） |

导读只接受 `flow`：导读没有经过独立审核，不应该在里面放未经核对的数字。

这样设计的原因：

- 让模型直接写 Mermaid，常见结果是语法错误导致画不出来，还可能夹带指令或 HTML。结构化 JSON 由我们生成 Mermaid 文本（`flowToMermaid`）：节点 id 重新编号（避免 `end`、`graph` 这类关键字），标签中的引号、`#`、`<`、`>`、反引号和 `|` 全部转成实体编码，渲染仍使用 `securityLevel: "strict"`。
- 柱状图用纯 HTML 绘制，从 0 开始，按最大绝对值等比。

**提示词与审核。**

- 讲解层次在“先建立直觉”之后新增“看图理解”。
- 流程图要求按论文的实际结构绘制，只能合并步骤，不能发明组件或连接；链条不超过 5 个节点时从左到右排，更长的从上到下排。
- 柱状图只用于实验主题：要么是原文表格中同一行或同一列、同一 split 和单位的数字（包含基线），要么是明确标注的教学数据。
- 独立 Reviewer 新增第 7 项检查：节点、箭头和分组是否与原文一致，`paper` 数值是否与原表完全一致。

**呈现。**

- 图下方固定显示来源说明：流程图是“讲解示意图：根据原文整理，不是论文原图”；柱状图写明数值是来自原表还是教学构造。
- 宽图最多缩到原始宽度的 85%，再宽就在图框内横向滚动。图框使用 `contain: inline-size`，不会撑宽正文列。
- 绘制失败时按箭头逐行列出同样的内容。
- 保存到笔记时，流程图导出为 Mermaid 代码块，柱状图导出为表格。
- 输入、输出节点用圆角框，不用胶囊形：Mermaid 的胶囊形每个节点会生成约 43KB 路径数据，其他形状几乎不增加体积。
- 格式模板（`docs/design/paper-guide/`）新增导读全景图、主题流程图、实验柱状图和文字版示例。流程图用应用同版本的 Mermaid 和主题变量预渲染，深色、浅色各一份。

## 并行生成

`PAPER_PARALLEL_REQUESTS = 3`（`crates/runtime/src/paper_reading.rs`）：同一个讲解任务最多同时进行 3 个模型请求。

- **逐页识别**：`next_page()` 从“同一时间只有一页”改为“运行中的页少于 3 页时，返回下一页”；各页可以按任意顺序完成，结果仍绑定到各自的尝试（session id）。
- **主题讲解**：初稿、独立审核、修订和复核作为任务调度。`next_lesson_jobs()` 按阅读顺序选出可以开始的主题，每个主题同一时间最多一个请求。不同主题互不等待：主题 1 在审核时，主题 2、3 可以同时生成初稿。
- **单一写入者**：请求放在 `FuturesUnordered` 中运行，但只有调度循环修改任务状态并保存。所以整行 CAS 保存（`save_paper_reading_run`）保持线性，审计记录和尝试次数都不变。
- **熔断**：只统计主题请求（审核不可用时记录在主题上，不计入）。熔断后不再启动新请求，等在途请求结束并记录结果后再报错暂停，不会留下“运行中”的尝试。
- **取消**：不再启动新请求。在途请求收到同一个取消标志后结束，结果不保存（取消命令已接管保存状态）。
- **Reviewer 并行**：每次审核都会清空并重设 Reviewer 环境变量，两个审核同时进行会读到空配置。现在 `tools::prepare_llm_review` 在锁内应用环境并解析出端点、模型和密钥，网络请求在锁外并行。ChatGPT 网页版 Reviewer 只有一个浏览器会话，仍然串行。
- 导读是单个请求，仍在所有页识别完成后进行；追问本来就独立，不受影响。

**预期效果。** 服务商允许并发时，逐页识别和主题阶段的总耗时大约降到原来的 1/3 到 1/2（受最慢的主题和审核轮数影响）。本轮没有用真实模型测量。

## 仍待验证

- 用真实的 DeepSeek、MiniMax 端点跑一整篇论文，记录并行前后的总耗时和 429 限流情况。并发数目前是常量 3，还不能在设置里调整。
- 并行开始的第一批主题请求会同时发出，此时讲解开头还没有进入缓存；这一批的缓存命中会比串行时略低，后续请求不受影响。
- 模型给出的图是否真正有助于理解，需要结合具体论文人工评估。Reviewer 看不到原图，只能对照原文文本核对图中的结构。
