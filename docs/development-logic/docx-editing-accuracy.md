# DOCX 编辑准确性

实现日期：2026-10-08。目标是精确修改已有 Word 正文，并避免公式转换错误被当成成功。此功能接在 Desktop 与 CLI 共用的 runtime/tools 层，没有新增完整 Word 可视化编辑器。

## 已有文档的局部修改

`read_docx` 返回文件 SHA-256 版本、段落 id、可修改文本片段和原生公式边界。正文、表格内段落、页眉页脚及脚注/尾注均可索引；`read_file` 和 `read_files` 对 DOCX 使用同一读取路径。批量读取将当前项目绑定传入每个工作线程，避免相对路径落到其他项目。

`edit_docx` 必须携带当前版本和精确段落 id。匹配必须在一个可修改片段内唯一，可以跨文本 run，但不能跨公式、链接、书签、对象或引用边界。替换文字采用首个匹配 run 的格式；未匹配文字及其格式保留。实现只替换选定 `w:t` 的内容，按 XML 解析器给出的范围写回，保留未修改 XML 以及 ZIP 内其他部件。它不通过整段 `paragraph.text` 赋值或整份文档重建来改正文。

批次先在内存验证，全部成功后原子替换文件。发布前再检查原文件版本；失效版本、重复匹配及失败批次不写入。旧的通用文本写入工具拒绝 Word 扩展名，避免把 DOCX 写成普通文本。

修改记录接入现有 change ledger，保存修改前后的原始二进制快照。`change_revert` 检查修改后哈希再恢复原始 ZIP 字节；有外部修改或文件已丢失时报告冲突。审计写入失败时尝试按字节检查并回滚，不覆盖后续外部修改。Review 界面的快照是明确标注的文字预览，公式占位符不能作为公式内容的验证依据。

保护范围：带修订、域、受管理内容控件或兼容性备用表示的段落拒绝普通正文修改；带数字签名的文档拒绝修改。当前只支持 transitional OOXML 的 DOCX；旧二进制 `.doc`、加密文件及 strict OOXML 需要专门转换/编辑。当前接口不新增段落、不改公式节点或表格结构。文件上限 64 MiB，单个文档 XML 上限 16 MiB，单次 1–64 项修改。

保存/撤销的文件比较与替换在文档锁内完成，快照和审计记录在释放文档锁后写入。不同路径可能共用同一组锁，不能将快照/审计锁嵌套在文档锁中。确定性回归专门构造文档路径和 ledger 路径共用锁的情况，检查修改和精确撤销均能完成。

## 公式生成
保留已有 `python-docx + latex2mathml → OMML` 链路，修复交底与申请两个独立分发副本：

- LaTeX 别名按完整命令匹配，避免将 `\left`、`\leq`、`\geq` 误改。
- 重音、上下横线、独立公式上下限、伸缩括号、矩阵/分段列对齐使用对应原生数学结构。
- 区分行内/独立公式；继承显式字体变体，保留空底座上标以及数学圆圈字符的身份。
- 未识别命令、不支持的结构和重音明确失败，避免简单摊平结构后报告成功。
- 默认要求全部公式生成 OMML。有图片/原文回退则转换失败且不发布文档；只有显式 `--allow-math-fallback` 或 `--no-omml` 才允许回退。统计保留，不能把回退文档称为全公式可编辑。
- Markdown 无法无损 UTF-8 解码时拒绝转换；完整 DOCX 保存到同目录临时文件成功后才替换目标。申请和审查意见的专用保存入口同样使用原子保存；审查意见原有的禁用原生公式模式保持其明确设置。

原生 OMML 是 Word 公式编辑器可修改的结构；存在 OMML 节点和格式校验通过，不证明任意 LaTeX 的语义、数学推导或页面显示均正确。复杂宏及未覆盖格式仍需具体样本验证。

## 方案选择与验收

当前生产路径使用 Rust 的 `roxmltree` 和 `zip` 做限定范围的 OOXML 编辑，复用现有运行时、文件边界和审计记录；没有引入 .NET 运行时或 Office 服务。开源 Open XML SDK 3.3.0 在本次验收中作为独立格式校验器使用。Pandoc、MathLive、ONLYOFFICE 等选项仍见 [此前调研](word-editing-open-source-options.md)，不能将其视为已经集成。

回归样本包含中文跨 run 文本、混合粗体/斜体、表格、页眉、9 个原生公式，以及分式、上下标、根号、重音、上下横线、求和、极限、矩阵、分段和伸缩括号。Rust 检查修改后所有公式 XML 和未修改部件字节保留，旧版本拒绝、批次原子性、审计失败回滚及原文件精确撤销；Python 对两个公式转换副本执行相同回归。

真实样本通过 Open XML SDK 的 Office 2019 结构校验。当前机器渲染尝试因 `soffice.exe` 不在 PATH 而失败；没有完成 Word/LibreOffice 的页面比较或目标 Word 的编辑、保存、重开验收，不能声明页面显示保真已通过。安装版应用需要重新构建/更新后才能使用代码中的新工具。
