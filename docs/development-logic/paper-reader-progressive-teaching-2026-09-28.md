# 论文讲解：由浅入深的分层教学、独立审核与问题修复

日期：2026-09-28。依据当天对文献库“论文学习”功能的审查，本轮修复了审查列出的实现缺陷，并按用户要求把讲解改成真正简化概念、由浅入深的结构。独立 Reviewer 重新接入讲解流程。本轮没有真实模型的整篇验收，内容质量仍需按下文“仍待验证”补测。

## 讲解协议 paper-guide-v2：由浅入深

**论文导读（outline）**

- `oneSentence`：用一句新手能懂的话说明论文解决什么问题、核心思路是什么。
- `glossary`：3–10 个关键术语，每个用一两句大白话解释。
- `topics[].level`：`foundation`（打基础）→ `core`（核心思想）→ `advanced`（深入细节）。解析后按层级稳定排序，阅读路线总是由浅入深；`prerequisites` 标注学习这一主题前应先读懂的术语或前序主题。
- `relevance`：仅在项目有进行中的目标时，写这篇论文与读者研究的关系。目标文本只是读者背景，不是论文证据；没有提供目标时，解析会清空这个字段，避免编造联系。

**单个主题（lesson）按层递进**

1. `plainSummary`：一两句话，不用符号和术语。
2. `analogy`：生活类比，并写明“类比不成立的地方”；没有忠实的类比时允许为空。
3. `prerequisites`：新手可能缺的背景概念，每个配一个极小的例子。
4. `intuition`、`notation`、`assumptions`、`steps`（先讲整体，数学放在最后）。
5. `example`：必填的分步例题。
6. `misconceptions`：新手容易想错的地方及纠正，例如“不变/等变”“界/保证”这类相近概念的混淆。
7. `evidence`、`checkQuestion` / `checkAnswer`。

**提示词**

- 不再写死“AI/ML 论文”。
- 读者设定为“有一般科学素养、但不熟悉本领域专门概念”。
- 写作规则：短句，一段只讲一个意思，先具体后抽象；术语首次出现即定义；只简化措辞，不简化结论；简化时省掉了条件要说明；不把“may / suspect”写成确定结论。

**阅读界面**（`PaperGuideView`）

- 导读页依次为：一句话看懂 → 与你的研究 → 论文脉络 → 关键术语 → 分级阅读路线。
- 主题页提供“入门 / 完整”阅读深度。入门模式显示一句话、类比、先补基础、直觉、例题、误区和自测；点“继续深入”再展开符号、前提、逐步推导和原文证据。
- 旧版（v1）讲解缺少分层字段，界面自动按原样完整显示。

## 独立审核与一次修订

- 每个主题生成后，经现有 Reviewer 通道（`run_paper_lesson_review`）独立核对。
- Reviewer 的配置、上下文和凭据都与 Executor 分开；Reviewer 与 Executor 用同一模型时直接拒绝，不产生审核结论。
- Reviewer 收到的是该主题原始 PDF 页的文本层与讲解草稿，按严格 JSON 返回 `pass` / `needs_revision` / `insufficient_evidence` 和问题列表。
- 若结论为 `pass` 却列出严重或重要问题，按 `needs_revision` 处理。
- `needs_revision` 时自动派发一次修订：新的 Executor 轮次重新读取原图和原文，附上审核意见与上一稿（明确标注上一稿不是证据）。修订稿随后复核。修订失败时保留第一稿，审核问题对读者可见。
- 未配置 Reviewer 或调用失败时记为 `unavailable`：讲解照常可读，但显示“未经独立审核”。用户配置 Reviewer 后点“补做独立审核”即可补审，已完成的讲解不必重新生成。
- `review_required` 的新讲解只有全部主题完成审核流程才进入 `guide_ready`。`reviewStatus` 与 `reviewCounts` 只由 Reviewer 结论产生，执行器自检和任务完成都不会改变它们。
- 已知限制：审核通道只能读文本，看不到页面图像。仅依赖图表的内容由 Reviewer 标为无法从文本核对，不会被猜测为通过。

## 追问与选区讲解

- 每个主题和导读页都能继续问：“讲得更简单”“再举个例子”“为什么成立”或自由提问。每一步推导旁有“这一步没懂？”，回答显示在对应段落下。
- 回答走无工具、只读原文的 Chat 轮次：重新读取该主题的原页图像和文本，讲解草稿只作为线索。
- 追问存在独立表 `paper_follow_ups`，生成任务运行中也能提问，不会与任务记录的版本比较保存冲突。
- PDF 选中文字后新增“由浅入深讲解”动作，与翻译并列，结果可以保存为标注。
- 主题可以“保存到笔记”，写入该文献的笔记，附原文页码和审核状态。

## 流程重排：有文本层的页直接读原文

- 策略版本升为 `paper-source-only-v2`。有可用文本层（至少 200 个非空白字符）的页不再逐页调用模型识别，状态为 `not_required`，直接进入导读和讲解。只有扫描页、纯图页等无文本层的页面才先转写。
- 以前每篇都要先等全部页识别（15 页约 4.6 分钟）才开始梳理主线，现在大多数电子版论文可以直接开始。
- “原文识别”标签可按需“逐页识别这些页面”，用于重建表格和公式。

## 导读取证：页面信号与自适应预算

新增 `crates/runtime/src/paper_evidence.rs`，完全基于 PDF 自身文本层做确定性分析，不调用模型：

- 识别图注、表注（含罗马数字表号）、带编号的公式行、参考文献标题与附录标题，把每页标为正文、参考文献或附录。
- 文本预算按注水法分配：短页完整保留，剩余份额流向长页；正文权重 1，附录 0.4，参考文献不分配。超出预算的页保留开头与结尾，中间插入省略标记，不再只截取开头。
- 导读原图优先选择正文中的方法图、结果表和推导页，其次是首页；参考文献页不选。
- 无文本层的页面把模型转写作为“派生转写”提供给导读，并单独记录 `derivedTextSha256`，不能作为导读概述的引用来源。这修复了扫描件导读只能看到 8 张图、其余页面完全不可见的问题。
- 导读另附页面索引（各页角色和图、表、公式行数），只用于选页。

## 可靠性与存储

- **图像能力探测**：开始或追问前，对每个模型连接做一次探测：发送一张写着“58”的小图，模型必须读对。失败时明确报错，不会在网关丢图的情况下仍显示为“多模态解析”。探测成功结果在本次运行期间缓存。
- **连续失败熔断**：连续 3 次请求失败（鉴权、额度、端点不可达、拒收图像等）即暂停任务，保留已完成结果并报告最后一次错误。模型已回复但格式不合格不计入，交给有上限的重试处理。
- **单主题失败不再拖累其他主题**：某主题的原始证据无法组装时，只把该主题标为失败，其余主题继续生成。
- **切换界面语言后可以继续**：继续未完成任务时沿用任务自身的语言。
- **旧版本可读、不可续跑**：`latest_paper_reading_run` 优先返回当前协议下的最新任务；没有时返回最近的旧任务供阅读，界面提示按新版重新生成。协议升级后，已生成的讲解不再消失。
- **版本管理**：可以列出、切换当前 PDF 的各个讲解版本，也可以删除某个版本，一并删除其记录、原页图片、`source.pdf` 快照、追问和生成会话文件。文献被永久删除时，同步清理它的所有讲解版本。
- **记录修正**：`inventory_version` 改为已保存页级结果的数量；页级尝试新增 `textSha256`，记录随图像一起交付的文本。

## 仍待验证

- 本轮没有用真实模型整篇运行 v2 讲解、审核和修订。下一步用《Attention Is All You Need》及 2–4 篇不同版式的论文，检查分层讲解是否真正降低理解难度，以及 Reviewer 能否检出此前记录的“置换等变写成置换不变”、缩放意义被夸大、Table 2 列归属错误等问题；同时记录审核带来的额外耗时和 tokens。
- Reviewer 看不到页面图像。表格列归属这类问题仍需要能读图的审核通道，或更可靠的表格局部取证。
- 导读本身尚未经过独立审核，只有主题讲解经过审核。
- 任务记录仍整行保存；页面准备仍在前端串行进行。长论文的写放大和准备耗时留待后续拆分。
- Reader Model 尚未实现：理解检查的作答不会写回读者状态，追问也不改变后续讲解的难度。
