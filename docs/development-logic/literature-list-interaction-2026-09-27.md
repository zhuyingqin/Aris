# 文献列表的选择、键盘与删除交互

承接 [文献库界面与交互重构](./literature-ui-refactor-2026-09-27.md)。本次只调整列表与详情面板的交互规则，不改文献存储、导入或审核流程。

## 规则

- **当前行与勾选分开。** 当前行决定详情显示哪篇文献；勾选决定批量操作的范围。
- **多选手势。** Shift+点击（行或勾选框）从锚点勾选到当前行；Ctrl/⌘+点击切换单行勾选；Ctrl/⌘+A 勾选当前可见范围。
- **批量栏覆盖在表头上。** 批量栏不再插在表格上方，而是盖住表头（全选框保持可见），列表各行位置不变。
- **列表只占一个 Tab 停靠点。**
  - ↑/↓ 切换当前行，Home/End 跳到首尾；Shift+方向键扩展勾选。
  - →/← 展开、折叠或回到父条目；经过子条目时只移动焦点，不打开附件。
  - 空格勾选，Enter 打开（有 PDF 时打开阅读器，否则显示详情）。
  - Delete 移入回收站；Esc 先关闭窄屏抽屉，再清空勾选。
  - `/` 或 Ctrl/⌘+F 聚焦搜索框。
- **详情面板。**
  - 宽屏停靠时，用户收起详情后，点击行不再重新展开，需要通过「显示详情」恢复。
  - 窄屏（容器 ≤ 850px）时详情是抽屉：点击行会打开它，方向键浏览不会打开；Esc 关闭抽屉并把焦点还给当前行。
- **删除可撤销。** 移入回收站和从回收站恢复不再弹确认框。移入后显示「撤销」提示，8 秒后消失，也可按 Ctrl/⌘+Z 撤销；切换项目时提示立即失效。彻底删除和清空回收站仍需确认。

## 实现

- 纯函数和 `useNarrowerThan` 放在 `desktop/src/literature/libraryInteraction.ts`。
- 键盘事件在列表容器上统一处理；只有焦点在行本身时才响应行内按键，行内按钮和勾选框保留各自的行为。
- 虚拟滚动时，焦点所在行若已移出渲染窗口，由第一条已渲染的行接管 Tab 停靠点。
- 撤销调用既有的 `restorePapers`，行为与在回收站中手动恢复相同：移入回收站时从审核建议里移除的依据文献不会恢复到这些建议中。

## 验证

- 文献模块与动效接线：13 个测试文件、158 项 Vitest 测试通过；`npm run typecheck`、`npm run build` 通过。
- 在真实 Chromium 中使用浏览器预览数据检查：
  - 1440px：勾选前后三行的位置一致（218/299/376 px），批量栏与表头同位置、同为 34px 高。
  - 方向键、Shift 扩展、全选、Esc、Delete 与撤销、`/` 聚焦搜索均正常。
  - 800px：抽屉的 Esc 关闭与焦点归还正常。
  - 1100px：深色主题和英文界面下批量栏显示正常。
- 仓库中 `src/typeset` 与 `src/pdf` 的 41 项既有失败在未修改的提交上同样出现，与本次改动无关。

## 第二批：阅读、右键、排序与布局记忆

### 规则

- **详情页签在 PDF 旁边打开。**
  - 阅读器右侧的「信息 / 简报 / 证据 / 笔记 / 文件 / 相关」不再退出阅读器，而是在 PDF 旁打开侧栏。
  - 再次点击当前页签、点「PDF」页签、点 × 或按 Esc，都会收起侧栏。
  - 从笔记、证据或简报打开 PDF 时，该页签会自动显示在侧栏里，方便对照原文核对批注和证据。
  - 点「返回」回到侧栏当时显示的页签。
  - 右侧停靠的详情面板不再提供会让整个页面切换成阅读器的「PDF」页签，打开 PDF 统一使用「打开 PDF」按钮。只有在显示「需要 PDF」提示时，才保留这个页签。
  - 重复点同一页的证据或批注时，PDF 也会重新跳到那一页。
- **文献行右键菜单。**
  - 右键、Shift+F10 或菜单键打开。
  - 右键已勾选的行时，对全部勾选项操作；右键其他行时，先清空勾选，只对这一行操作。
  - 单篇时的菜单项：打开或获取 PDF、显示详情、问 Agent、复制引文、已读/未读、收藏、加入候选、排除、从分类移除（仅在分类视图）、移入回收站。
  - 多篇时，打开 PDF、显示详情、问 Agent 换成「下载 PDF」，且只下载还没有 PDF 的文献；已读/未读和收藏不出现。
  - 回收站中只有「恢复」和「彻底删除」。
  - Esc 关闭菜单，焦点回到这一行。
- **列头排序。**
  - 点击「标题 / 出版物 / 年份」列头按该列排序，再次点击切换方向，并通过 `aria-sort` 标明当前方向。
  - 排序下拉框新增「出版物」，旁边增加升序/降序切换按钮。
  - 文本默认 A→Z；日期、分数和数量默认从大到小。缺少该字段的文献无论升序降序都排在最后。
- **布局记忆。**
  - 保存在本机 `localStorage`：导航开关、用户主动收起的详情、导航和详情宽度、列宽、排序方式。
  - 数据无法读取或无效时，回到默认布局。
  - 面板分隔条可以用方向键调宽（Shift 加大步长），Home/End 跳到最小/最大宽度，双击恢复默认宽度。
- **窄屏双击。** 窄屏下单击行后约 250ms 才打开详情抽屉，避免抽屉盖住行，让双击的第二下落到抽屉上。双击仍然会打开 PDF。
- **活动面板。** 移入回收站时不再自动展开活动面板，记录仍会写入活动日志；界面上的反馈由撤销提示负责。

### 实现

- 详情内容抽成 `renderDetailContent(paper, tab)`，停靠面板和阅读器侧栏共用同一份内容。
- `LibraryMenuPopup` 从 `LibraryActionMenu` 中拆出，按钮菜单和右键菜单共用同一套键盘操作、定位和关闭规则。
- 表头单元格显式声明 `role="columnheader"`。表格用 CSS grid 布局时，Chromium 会把表头当作普通单元格，导致 `aria-sort` 失效。

### 验证

- 文献模块与动效接线：13 个测试文件、166 项 Vitest 测试通过；typecheck 与 `npm run build` 通过。全量测试中只有 `src/typeset`、`src/pdf` 的 41 项既有失败。
- 在真实 Chromium 中用浏览器预览数据检查：
  - 列头排序与方向切换正常。
  - 右键菜单出现在指针位置，Esc 后焦点回到行；Shift+F10 也能打开菜单。
  - 分隔条用方向键调到 252px，重新打开页面后保持 252px；收起的详情和排序方式也被恢复。
  - 1440px 下阅读器侧栏宽 420px，PDF 保持打开；640px 下侧栏改为覆盖在 PDF 上。
  - 无运行时错误。浏览器预览中 PDF 本身显示「加载失败」，因为预览不能读取本地文件，这是预期行为。
