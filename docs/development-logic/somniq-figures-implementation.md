# SomniQ Figures 首版实施记录

日期：2026-10-06。实施依据是[当前 AutoFigure 集成计划](autofigure-minimal-change-integration-plan.md)。本次交付独立的科研绘图工作区，作为 SomniQ Desktop 的一级入口；项目、账户、SomniImage、Executor、独立 Reviewer 和请求用量仍使用 SomniQ 的基础设施。

## 已实现的使用流程

在左侧“科研绘图”入口选择当前本地项目，在一个描述框中写清图的内容（首行作为任务标题，不足 50 字原样使用），从四个风格预设中选一个。上传 PNG/JPEG/WebP 即为导入模式且不重新生图；未上传时先由所选 Executor 理解描述与风格、整理生图提示词，再由 SomniImage 生成参考图。生成或导入后先预览图片，可圈选区域或显式选择整图修改；每次修改同样先由 Executor 结合当前图、选区、所属分支的历史要求和本次要求整理提示词，再调用图片编辑。用户确认所选版本后，才执行直接视觉 SVG 重建、本地验证和 PNG/PDF 渲染、独立 Reviewer 审查。SVG 无效或审查未通过时最多修订一次，随后再审查。没有 SAM、fal.ai、Roboflow、RMBG、Hugging Face 或 Python 后端。

新建任务由用户为 Executor、Reviewer 和生图分别选模型，默认分别为当前 SomniQ Executor、设置中的 Reviewer 和 SomniImage 默认模型；选择只作用于该任务，不写回设置。Executor 候选为已验证连接与账号已同步的文本模型。Reviewer 候选为账号已同步的文本模型及设置中的 Reviewer：选设置以外的模型时，用账号凭据直接构造一次性连接，不改动进程级 Reviewer 环境变量，因此不影响 Chat 的独立审查。两角色必须是不同模型（界面把 Executor 改到当前 Reviewer 时自动换到下一个候选），且不共享对话。模型、端点、传输方式和绘图推理策略组成连接签名，任务启动时检查配置快照。

用户确认图片后，首次使用每个角色/连接才发送随机四位数字的真实 PNG 检查图片能力；结果按项目和连接签名缓存，每次探针进请求账本。Executor 探针失败就停止重建。Reviewer 确认不支持图片时仍可审查结构，但最高状态为“结构通过／视觉待检查”；服务错误、额度错误或路由错误不会被当作无视觉能力。视觉通过要求 Reviewer 实际收到原图和当前版本的导出 PNG。

SVG-Edit 7.4.2 从锁定 npm 依赖打包到本地，提供画布和 SVG 源码编辑。支持改字、移动、分组、撤销/重做以及保存不可变版本。源码未保存时不把它替换成旧画布内容；切换项目和关闭窗口沿用 SomniQ 的未保存/运行中任务保护。历史版本可查看、继续修改后保存成新版本，并单独导出 SVG/PNG/PDF。编辑、保存、导出没有模型请求。重新审查是显式的额外一次 Reviewer 调用。

### 界面布局（2026-10-06 改版）

参照上游 `demo_canvas.png` 的"画布优先 + 浮动面板"结构，按 SomniQ 设计令牌重排，不改变任何调用、保存或审查语义：

- 工作区顶部为面包屑（项目 / 图标题）和"描述 → 生成 → 编辑 → 导出"四步条；四步只从 manifest 推导，生成失败或结果不明显示警示而不是完成，状态标签与 Executor／Reviewer 身份同排显示。
- 新建时左侧为规格面板，右侧为棋盘格画布预览：已添加参考图则预览该图，否则说明可编辑 SVG 将在此打开；图片可拖到描述框或画布。规格面板包含带字数的描述框（附加参考图入口、描述为空时显示快速示例）、带缩略图的四个风格预设和三个模型下拉（Executor／Reviewer／生图；已有参考图时生图下拉停用）。SVG 输出上限由后台复用 Chat 策略，界面不再提供额度选项；底部固定主按钮，并显示预计调用次数与最多次数。
- 已有任务的规格不再占用画布左侧：右侧检查器分"审查与产物"和"任务输入"两页，后者显示冻结的描述、风格、模型、输出上限、任务 ID 与详细运行进度，并可"用相同输入新建"。新任务沿用原参考图（导入或已生成的均可），因此不会重复生图。导出改为下拉菜单（SVG／PNG／PDF 并注明用途）。
- 未照搬参考稿的元素检查器、图尺寸与配色、模板和多页：元素属性由 SVG-Edit 自身面板负责；尺寸与配色需要后端语义（生图尺寸、重建画布约束），尚未实现。
- 左侧绘图列表悬停或聚焦时显示删除按钮，确认后移除该任务目录（SVG 版本、参考图、manifest 与请求账本），不可撤销。运行中的任务不能删除；删除时持有任务锁，启动或审查不会在删除中途开始。
- 任务页顶栏显示视图切换（画布／对照／SVG 源码）、版本、保存、审查（标注 1 次调用）与导出。详细阶段"视觉检查 → 参考图 → 重建 → 独立审查 →（修订）→ 定稿"同样只从 manifest 推导，运行中显示在画布等待卡片里，完成后在检查器"任务输入"页查看。
- 右侧"产物与审查"检查器停靠在画布旁，不覆盖图形。它显示审查结论、原图与导出预览缩略图（应用内看图器打开）和不可变版本列表。请求账本默认折叠为画布左下角的胶囊，展开后逐条列出阶段、模型、停止原因、输出／上限与耗时，并汇总未决请求。
- SVG-Edit 外框通过只含明暗模式与十六进制强调色的 `theme` 消息跟随应用主题。图标是白/黄位图，所以工具托盘在两种主题下都保持深色。载入后自动适配画布视野；缩放不进入 SVG。

纯展示推导集中在 `desktop/src/figures/figureModel.ts`，有单测覆盖。

## 调用额度与失败处理

导入正常为重建和审查两次核心调用，自动流程最多四次；生图增加一次 Executor 提示词规划，正常四次、最多六次。首次能力检查另外最多两次，因此生图自动流程的总请求预算为八次。每次用户提交的 PNG 修改另计一次 Executor 和一次图片编辑，不占自动 SVG 重建预算；总账本仍最多 200 条，图片版本仍最多 100 个，修改前须保留两个请求名额。语法修复与质量修订共用一次机会。共享客户端为此流程关闭 HTTP、兼容参数和流式重试，使用冻结的传输方式，失败不会隐式多次收费。

`x-opencode-session` 是 OpenCode 调用路由的要求，不能视作模型能力。绘图 Executor 直接复用 Chat 客户端装配；OpenCode 直连域名或显式 OpenCode 固定连接启用此头。账号网关入口还须从首次调用就接收稳定会话元数据：共享解析器按当前端点与已配置的 `newapi_executor_base_url` 匹配启用传递，Executor、Reviewer 和摘要客户端采用同一判断。此举不把网关所有渠道或 model 标记为 OpenCode；网关选择实际渠道后，由需要会话的渠道转发此头。未知自定义端点不继承账号网关策略。客户端没有 NewAPI 实际渠道 ID，因此没有按端点/凭据/model 记忆错误的注册表；同一 model 后续可能轮询其他提供方，不能继承上次错误的路由身份。

固定 OpenCode 代理连接可把 `executor_provider`、`reviewer_provider` 或 `summarizer_provider` 显式设为 `opencode`，同时提供该连接自己的端点与凭据；这声明的是固定上游连接，不是 model 的属性，也不能拿来标记会轮询多个提供方的公共入口。账号模型同步保留此连接；主动切回账号模型则恢复账号网关连接及其会话元数据传递。Reviewer 的账号网关端点通过 `ARIS_REVIEWER_ROUTING_SESSION_BASE_URL` 传入共享工厂，与 Reviewer 实际端点匹配才启用；强制应用设置时清除旧值，切换到其他端点后不会残留。显式连接的环境配置仍为 `ARIS_REVIEWER_PROVIDER=opencode`，配合自身的端点、凭据和 model。连接会话传递标记纳入绘图配置签名，变更后旧待运行任务应重新准备。

首次未知代理返回明确 `MissingSessionID` 错误时，绘图单请求模式保存拒绝并提示配置固定 OpenCode 连接，不补发、不标记后续同名模型调用。普通 Chat 保留本次调用内的兼容协商，但不会把识别结果缓存到下一次调用。会话 ID 由项目路径摘要、绘图 ID 和角色生成，在探针、重建、修订及后续审查间稳定，两角色相互隔离。若已发送会话头仍收到该错误，共享客户端提示网关没有转发该头，仍不自动补发。

新建任务的 SVG 重建和一次修订复用 Chat 的输出策略，不另建绘图模型上限表：Anthropic 使用同一个 `max_tokens_for_model`（Sonnet/Opus/Fable 为 128,000，GPT/o3/o4 为 16,384，其余为 64,000）；OpenAI-compatible 的 Chat Completions 默认不发送上限，仅复用有效的 `ARIS_OPENAI_MAX_TOKENS` 覆盖；Responses 与 Chat 一致，不发送上限。值在准备任务时冻结并写入 `outputLimit`，0 表示未发送输出 token 字段、由服务默认值决定，账本的 `maxOutputTokens` 使用同一值。以前记录 8K–50K 的任务保留原值，不修改历史账本或在执行时升额。视觉探针仍为 1,024，独立 JSON 审查仍为 8,192。

单请求模式保留轻量推理。服务的输出上限仍可能包含推理 token；截断后保留原始输出，提示切换推理更少的 Executor 或简化描述，复用输入新建任务，不自动重试、扩额或切模型。字符数与输出 token 的差值只是估算，不能据此确认实际隐藏推理用量。

DEV-02 暴露 Reviewer 的 2K 预算可能在最终 JSON 前耗尽。本轮 Case 11 将独立审查固定预算改为 8,192，并在每次请求的 `maxOutputTokens` 中记录；截断仍保持待检查，不自动升额或重发。此前开发样例的 2K 记录保持其原始配置。

保留服务返回的停止原因、真实用量、耗时和原始输出。`length`/`max_tokens` 等计为确认额度截断；不完整流单列，不能据此认定直接重建方法失败。截断后可在源码页手动修复并保存，也可由用户另建明确额度的新任务。

请求提交前先保存账本。重启时，已提交但未记录结果的请求变为 `unknown`，不重发；没有未决请求的中断任务保留为草稿。未决记录不被当作零费用或成功，自动流程和额外审查均不会越过未决记录。已保存的 SVG 仍能本地修改、导出。新任务必须由用户明确启动。

## 工程边界与产物

| 位置 | 职责 |
| --- | --- |
| `crates/runtime/src/figures.rs` | 项目目录约束、manifest、请求预算、恢复、来源/版本 SHA-256、原子保存和父版本冲突检查 |
| `crates/executor/src/bounded.rs` | 单请求执行、取消、部分输出与停止原因；两侧复用已有模型客户端 |
| `crates/chat/src/figures.rs` | 绘图 Executor、独立图片消息、重建和审查提示 |
| `crates/tools/src/figures.rs` | SVG 校验、可编辑性分类、固定 resvg 0.45.1 / svg2pdf 0.13.0 本地渲染与字体指纹 |
| `desktop/src-tauri/src/figures.rs` | 项目绑定的原生命令、任务控制、图片探针、流程编排、Reviewer 证据和导出 |
| `desktop/src/figures/`、`desktop/figure-editor/` | 独立应用页面、本地 SVG-Edit、仅编辑文档的隔离消息桥 |

图形按 `editable_vector`、`hybrid`、`raster_preview` 分类；整图 PNG 包装无法通过本地结构门槛。允许受控的内部 marker、clipPath、渐变、图形引用和内嵌栅格图；禁止脚本、事件处理、DTD/实体、foreignObject、外部资源及危险 CSS。校验在模型返回、文件读取、画布保存时使用同一边界。

编辑器使用不授予同源权限的 sandbox iframe，消息校验源窗口和每次挂载的随机通道。只接收文档载入和序列化，不接收项目路径、账户或原生命令。Windows 上 wry 忽略 main-frame-only，把 Tauri 初始化脚本注入所有子框架，`ipc`、`isTauri`、`__TAURI_INTERNALS__` 以不可配置属性出现在编辑器框架中、无法删除；因此桥接层不以"全局是否存在"判定，而是切断两条传输：`ipc` 自定义协议被 CSP `connect-src 'self'` 拦截，postMessage 回退路径唯一出口 `chrome.webview` 在启动前移除，移除失败才停止初始化。CSP 同时限制本地代码与资源。原生 `somniq-figure` 协议仅提供固定目录中的编辑器静态资源并允许其模块在 opaque-origin 框架中加载；主应用及任意项目文件的跨域权限不扩大。SVG-Edit 的 transformed/clip 分组改字、文字撤销记录和移动状态通知在桥接层适配，未改动供应商源码。许可证随编辑器一起打包。

产物保存在 `.somniq/artifacts/figures/<run-id>/`：

```text
manifest.json                  # 配置、来源、版本、每次请求、用量和当前独立决定
figure.source / figure.png      # 固定来源快照，JPEG/WebP 按实际扩展名保存
template.svg / current.svg      # 首次成功结果与最新编辑源
versions/0001.svg / .png / .pdf # 不可变版本、预览和论文导出件
request-01.response.txt         # 模型原始输出，包括可恢复的不完整草稿
final.svg                      # 仅当前版本完整审查通过后产生
generation.json                # 生图模式的已有 SomniImage 返回记录
```

保存以当前 SVG 哈希为父版本条件，冲突时保留前端草稿。人工保存使旧审查和 `final.svg` 失效。Reviewer 的图片证据与来源、SVG、PNG、渲染器和字体指纹关联；发现字体或渲染器变化时撤销旧视觉结论。用户重新审查时先免费生成新渲染版本，再提交一条 Reviewer 请求。

## 绘图界面一致性

绘图工作区和 SVG-Edit 的外框共享主应用的背景、边框、文字、强调色、字体和字号。浅色模式使用浅色工具栏和单色图标；深色模式及自定义配色同步更新。主操作按钮与选中状态使用同一个强调色，标题、视图切换和任务操作分层排列。编辑器隐藏与外层重复的文件菜单及标题，保留本地绘图工具和真实颜色选择；图内 SVG 的文字、填色和笔画不受界面主题影响。适配在包装层完成，不修改供应商源码。

宽屏审查面板停靠在画布旁，减轻卡片阴影。进入 960px 及以下窗口时收起审查面板，760px 及以下同时收起绘图列表；用户仍可主动展开，窄屏列表提供关闭及背景点击收起入口。初始画布视角随窗口/停靠面板尺寸适配；用户操作编辑器后保留其缩放和移动视角。主题及视角适配不改动序列化 SVG，也不标记未保存编辑。

本次 UI 专项的 24 项 Vitest、TypeScript 检查和生产前端构建通过。真实 Chromium 验证主题与受限色值桥接、首次缩放适配、编辑后视角保留、中文改字、clip 分组拖动、撤销重做和保存重开；本地 ESN 图在 2048/1280/960/720px 布局检查通过。展示夹具仅只读载入本地绘图，所有提交接口禁用；没有发起模型或审查请求。桌面 debug 程序使用 `tauri/custom-protocol` 重新构建通过，携带本地前端资源。原生 WebView2 的实际操作验收仍沿用下文的未完成记录。

## 本轮实际验证

取消组合回归确认 SVG-Edit 7.4.2 的原生解组只传递 transform/filter/opacity，遗漏父组的字体、对齐、填色和描边继承。ESN 图把 `Times New Roman, Times, serif` 放在外层 `g`，拆组后文字回落到编辑器界面字体；相对字号也失去原来的上下文。包装层 `preserve-group-styles.js` 在原生解组前记录直接子元素的计算展示属性，拆组后仅固化确实变化的属性，保留子元素明确设置的样式、嵌套 tspan 和原生变换处理。原生解组命令、展示属性修复和子元素变换合并为一个撤销动作；额外记录子变换以补齐纯旋转分组的原生撤销遗漏。无需模型调用，不改动用户的真实图形或历史版本。

真实 Chromium 回归覆盖继承字体、em/% 相对字号、粗斜体、锚点、填色/描边、嵌套拆组、拆组后字号编辑、缩放/旋转组、单次撤销重做和序列化重开。比较文字内容、计算样式及 SVG 文档坐标，排除工具栏展开造成的屏幕位置变化。用户 ESN 图只读输入经过连续两次拆组、两次撤销及保存重开，77 个 text/tspan 的内容、样式和文档坐标保持；不把这项 Chromium 检查说成原生 WebView2 操作验收。新增的浏览器输入变量 `SOMNIQ_FIGURE_EDITOR_UNGROUP_SVG` 可指定本地实际 SVG 进行同样检查。24 项绘图 Vitest、类型检查、生产前端构建及携带最终编辑器资源的桌面 debug 构建通过。

## PNG 预览和圈选修改（2026-10-06）

生成或导入图片后，任务停在 `image_ready`。用户先预览 PNG，通过自由圈选或矩形选区输入修改要求，也可添加多个区域、撤销或清除圈选。只有点击“修改选区”才提交一次 SomniImage 编辑调用；点击“确认此图并生成 SVG”后才进行视觉探针、重建、独立审查和既有的一次修订。生成原图与每次图片编辑均保持单次发送，失败不会切换到整图生成、自动重发或自动扩额。

图片编辑复用共享 `api::ImageApiClient` 的 `images/edits` 接口和当前 SomniImage 账户连接。已有生图任务按冻结的模型与连接校验；导入任务使用已配置的 SomniImage。[官方编辑接口](https://developers.openai.com/api/reference/resources/images/methods/edit)约定使用与原图相同尺寸的 PNG 蒙版，透明区域表示需要编辑的范围。界面将缩放及留白换算到原图像素，生成二值透明蒙版；后端验证格式、尺寸、有效选区与大小。尺寸一致的结果只将选区像素合成到原图。尺寸不同的结果保存为待采用图片，支持整图采用、缩放至原尺寸后仅应用圈选，或保留原图；用户先切换预览再选择，不报普通尺寸变化错误，也不会默默缩放或再次收费。圈外像素保护适用于选区合成；显式整图采用允许圈外内容变化。

原图 `figure.source` 保持不变，新图片以 `raster-NNN.image` 和 `rasterVersions` 记录不可变版本。每个版本保存父版本编号与哈希、修改要求、蒙版路径及请求编号。调用前持久化 `request-NN.edit.json` 与蒙版，调用后保存原始结果、用量与完成状态；手动图片编辑有独立账本种类 `manual_image_edit`，不占用自动 SVG 请求额度，但总请求数最多 200、图片版本最多 100。未决请求会阻止再次提交；程序重启不会将图片修改重新发送。正常的预览等待状态重启后仍可继续确认。

确认同时核对图片内容哈希和版本编号，支持先回看或选回原图再确认。若不同分支恰好具有相同像素，修改语义仍沿父版本编号追踪。已确认的修改要求会传给 Executor 和独立 Reviewer；既有 SVG 的参考图和审查证据保持固定。SVG 生成后的 PNG 修改保存为额外图片版本；面板底部仅保留“下一步”，直接衔接所选图片的 SVG 流程，既有参考图可直接回到 SVG。编辑面板移除新建任务及 PNG 下载按钮。

### PNG 编辑结果的尺寸处理
