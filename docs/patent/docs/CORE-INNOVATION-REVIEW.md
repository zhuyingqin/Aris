# 核心创新与专利重构意见

## 判断

当前申请的技术基础是真实的，但原稿把“输出摘要值”“重复计数”“大输出外置”“上下文压缩重建”写成了并列特征。这样容易被理解为把内容去重、缓存和限流几个已知机制拼接到智能体上，真正的技术闭环没有被凸显。

更适合作为当前申请主轴的概念是：**工具结果经过不同表示变换以后，仍然保持同一证据身份；运行时把这些证据身份写入可重放账本，并据此在下一次工具执行前决定是否允许调用。**

这里有三个表示层：

1. 工具执行得到的原始输出；
2. 为节省上下文而写入会话的引用式结果或预览；
3. 上下文压缩、恢复或重启后用于继续执行的账本状态。

如果三层使用不同身份，外置和压缩都会把旧证据伪装成新证据，循环控制就会失效。当前申请最值得保护的是这条跨表示的身份不变性，以及由确定性规则重放账本的机制。路径、预览、时间戳和调用标识只是证明该机制必要性的实现情形。

## 当前申请（A1）的核心保护组合

建议把 A1 的独立方法权利要求收束为以下连续闭环：

1. 对工具输入生成调用身份，对工具输出生成证据身份，并记录规范化规则版本、调用标识和完成顺序；
2. 对结构化输出进行确定性规范化，剔除只反映传输或运行时过程的易变字段；
3. 输出被外置、引用或压缩后，优先使用随表示携带的内容身份，路径和预览不参与证据身份计算；
4. 以“新证据、重复证据、空/无效结果”三个状态更新同一用户回合的账本；
5. 在新的工具调用执行前，同时检查当前无新证据状态、该调用身份的历史次数和该调用身份对应的同一结果连续次数；满足策略条件时生成不改变账本的合成拒绝结果；
6. 上下文压缩或恢复时，从持久化的调用—结果观察记录按相同版本重放账本，不重新调用模型或外部工具。

这样写以后，三重条件不再是孤立阈值，而是“证据状态 + 调用身份 + 结果身份”的执行前状态机。轮询工具的放宽属于工具能力描述带来的策略分支，放在从属权利要求中更稳妥。

## A1 中应明确的特殊性

### 证据身份跨表示保持不变

同一份输出可能被写入不同文件、截成不同预览、添加不同调用标识，甚至只剩下压缩后的结构化引用。若仍能通过内容身份把这些表示归并为同一观察，说明书应把它描述为“表示变换不改变证据身份”。这比“使用 SHA-256”更有保护价值，也避免把保护范围锁死在某种摘要算法上。

### 账本是可重放状态，而不是一次性计数器

压缩后重新计算不是简单恢复几个数字，而是以持久化的观察记录为输入，按同一规范化版本、同一回合边界和同一调用结果配对规则重放状态。重放不产生新的工具观察，不调用大语言模型，也不把合成拒绝结果当成证据。应在说明书中把这描述为确定性状态重建和一致性保持。

### 控制对象是“没有产生新观察的执行”，不是“模型说了相似的话”

模型可以改变措辞、检索词或参数，但只要结果仍映射到已知证据身份，就会延长无新证据状态；如果调用改变了来源、目标、机制或确实产生新的证据，执行仍然开放。由此可以把技术效果落在减少无效计算、网络请求和上下文增长，避免写成提高模型智力或回答质量。

### 合成拒绝结果必须与真实工具结果隔离

拒绝结果只描述控制器状态，不代表外部工具观察。若把它加入账本，拒绝本身会被误认成新证据并清零连续计数，控制器会被自己的反馈绕过。该排除规则应保留为从属特征和实施例。

## 从产品中抽象出的第二项专利候选（B1）

当前产品中比 A1 更具业务辨识度、也更值得单独检索的发明，是“面向候选识别的证据约束检索控制”。建议题名：

> 一种基于候选冻结与证据矩阵的研究智能体检索控制方法及系统

其核心技术链如下：

1. 识别用户问题属于候选对象确认任务时，先从问题中提取 4—6 个稳定线索，为线索分配唯一标识、是否必需和证据权重，并在本次任务内锁定；检索词只能用于路由，不能新增或替换锁定线索；
2. 在探索阶段从结构化来源收集候选对象，对不同来源、URL、版本和标题进行规范化合并，形成候选集合；
3. 达到最低的实质性探索条件后冻结候选集合，进入核验阶段；核验阶段禁止引入冻结时不存在的新候选，防止模型为了支持既定答案不断扩大搜索范围；
4. 将每次来源窗口保存为不可变证据锚点，并把证据锚点绑定到候选标识、线索标识、来源窗口标识和可验证的原文引句；支持、反驳或排除结论必须通过引句存在性校验，只有语义相似而没有直接引句的记录只能是待定；
5. 形成候选×线索的稀疏证据矩阵，记录支持、反驳、排除、待定、直接性和引句；
6. 根据多次探索的相对排名和已开始核验的候选构造动态比较前沿。候选只有在所有必需线索得到直接支持，并且其已确认权重严格高于比较前沿中其他候选的乐观剩余权重时才进入“可确认”状态；
7. 运行时根据结构化状态输出“已确认/高置信/未确认”标签，并在证据不足时阻止任务伪装成完成或明确暴露剩余不确定性；任务重启或上下文压缩时从检查点恢复候选、线索和证据状态。

B1 的特殊性不是“让模型搜得更多”，而是把开放式检索改造成由运行时强制执行的**先锁定目标、再冻结候选、逐格核验证据、比较反例、最后输出置信度**的技术状态机。与 A1 的工具空转控制相比，B1 直接解决了确认偏差、无依据引用和搜到第一个相似结果就结束的问题，建议作为另一件申请或后续分案候选。

## 可单独形成的第三项候选（C1）

产品的 Executor→独立 Reviewer→修订闭环也可单独形成“基于角色隔离和审查快照的本地研究任务执行控制方法及系统”。其可保护点是：Executor 产物以版本化快照交给 Reviewer；Reviewer 只接收任务目标、产物和明确证据，不继承 Executor 私有上下文；通过/要求修改改变持久化状态；要求修改会使后续产物失效并回到同一任务的修订轮次；完成状态只能由独立 Reviewer 的带证据结论触发。这个方向与 A1、B1 的技术问题不同，不宜并入当前申请。

## 当前原稿的具体弱点与处理

| 原稿表达 | 风险 | 重构方向 |
|---|---|---|
| “内容摘要值 + 计数” | 容易落入通用去重或计数判环 | 改为跨表示的证据身份不变性 |
| 四个阈值并列 | 容易被认为是任意参数拼接 | 写成证据状态机，阈值仅为策略实例 |
| 仅从会话消息重建 | 压缩后消息可能已经不存在，公开不充分 | 说明持久化观察记录、规范化版本和确定性重放 |
| 按工具名称识别轮询 | 实现偶然、保护范围偏窄 | 改为工具能力描述或策略标签 |
| 策略变更指示写得很重 | 可能被理解为对模型思维的规则 | 作为可选的内部控制结果，主效果落在执行前门控 |
| 大体积外置单独展开 | 容易被认为是常见上下文管理 | 只作为证明“证据身份跨表示”的必要实施例 |
| Executor/Reviewer 与工具循环混写 | 技术问题和保护客体不一致 | 作为 B1/C1 分案方向单独准备 |

## 申请策略

当前 A1 可以继续作为“证据账本运行时控制”申请，但应以重构后的主权利要求替换原来的特征堆叠。B1 应先做独立检索，再决定是否立即申请；其说明书应围绕候选冻结、引句可验证性和动态比较前沿展开。C1 适合在任务运行时和独立审查实现稳定后单独申请。

上述判断是技术方案和撰写策略评估，不能替代代理师对新颖性、创造性、抵触申请和公开时间的正式意见。尤其是现有代码已经公开的部分，应由代理师重新确定申请日、权利要求边界和可主张的优先权事实。
