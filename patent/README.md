# A1 专利申请材料

一种大语言模型智能体的工具调用控制方法及系统 —— CNIPA 发明专利申请。

**LaTeX 是唯一来源**：`tex/` 下的 `.tex` 就是可编辑的正文，`output/CNIPA/` 下的 PDF 全部由它编译产生。不要去改 PDF，也不要再引入第二套 Markdown/HTML 来源。官网原始表格和逐项核对见 [`docs/CNIPA-TEMPLATE.md`](docs/CNIPA-TEMPLATE.md)。

## 目录结构

```
patent/
├── PATENT_STATE.json          # 流水线状态（/patent-pipeline 断点续跑用）
├── tex/
│   ├── build.cjs              # 编译全部 + 递交前形式核验
│   ├── cnipa.sty              # CNIPA 通用类版式（页眉框线、宋体 12bp、25/15mm 页边距）
│   ├── notes.sty              # 工作文档版式（可用表格、有页眉页脚）
│   ├── patfig.sty             # 附图的 TikZ 样式
│   ├── symbols.sty            # 宋体没有的符号（∧ ≥ ① …）的映射
│   ├── claims.tex             # 权利要求书            ┐
│   ├── description.tex        # 说明书                │ 递交件
│   ├── abstract.tex           # 说明书摘要            │
│   ├── drawings.tex           # 说明书附图（装订五幅）┘
│   ├── figures/fig1–5.tex     # 五幅附图，各自独立
│   ├── notes-prior-art.tex    # 现有技术检索记录      ┐
│   ├── notes-disclosure.tex   # 发明构建书            │ 内部工作文档
│   └── notes-draft.tex        # 递交前注意事项        ┘
├── references/cnipa/          # 官网 100001--100004 原始表格与指南快照
├── docs/CNIPA-TEMPLATE.md     # 官方要求与 LaTeX 映射
└── output/CNIPA/              # 编译产物（递交件、工作文档、合订本）
```

## 递交材料与装订顺序

《专利审查指南》第一部分第一章规定申请文件按下列顺序排列，`output/CNIPA/` 下的文件即按此顺序编号：

| # | 材料 | 文件 | 页数 |
|---|---|---|---|
| 〇 | 请求书 | 官方表格，在专利事务办理系统中填写，**本仓不生成** | — |
| 一 | 说明书摘要 | `output/CNIPA/说明书摘要.pdf` | 自动记录 |
| 二 | 摘要附图 | `output/CNIPA/摘要附图.pdf` | 自动记录 |
| 三 | 权利要求书 | `output/CNIPA/权利要求书.pdf` | 自动记录 |
| 四 | 说明书 | `output/CNIPA/说明书.pdf` | 自动记录 |
| 五 | 说明书附图 | `output/CNIPA/说明书附图.pdf` | 自动记录 |

摘要附图指定为**图 1**，图号须同时写进请求书。权项共 14 项（3 项独立 + 11 项从属），超出 10 项的 4 项产生附加费。

另有 [`output/CNIPA/合订本.pdf`](output/CNIPA/合订本.pdf)：封面 + 目录 + 上列全部申请文件 + 三份内部工作文档，按上述顺序串成一册，供通读、打印与存档。**合订本不是递交件**——递交的是各个单独文件，因为申请文件各部分须分别编写页码，且「一页纸上不得包含两种以上文件」。2026 年电子申请还须按 CNIPA 数据标准提交 XML，PDF 仅作纸面核对或系统要求的对应附件。

## 编译

```bash
node patent/tex/build.cjs
```

只编译某一份：

```bash
node patent/tex/build.cjs claims
```

不编译、只核验已有 PDF：

```bash
node patent/tex/build.cjs --check
```

依赖 TeX Live 的 `xelatex` 与 `pdfinfo`（两者随 TeX Live 一起装）。中间文件落在 `tex/.build/`（已 gitignore）。

## 正文怎么改

| 要改的东西 | 改哪里 |
|---|---|
| 说明书某一段 | `description.tex` 里对应的 `\p{...}`；默认输出首行缩进，需要段号校阅稿时给 `cnipa` 加 `numbered-paragraphs` |
| 加/删一项权利要求 | `claims.tex` 里的 `\claim{...}`，编号自动连续；但“根据权利要求 1 所述”这类**引用关系是写死的文字**，改顺序后必须手工核对 |
| 摘要 | `abstract.tex`，改完跑 `--check` 确认不超 300 字 |
| 某幅附图 | `figures/figN.tex`，节点用 `positioning` 串联，挪一步不会带崩后面的 |
| 版式（字号、页边距、行距） | `cnipa.sty` |

## 形式核验做了什么

`build.cjs` 每次编译后自动跑，任一项不过就是红叉：

- **缺字**——见下文，这是最容易漏的一项
- **孤标题**——小节标题排在页末、正文被甩到下一页
- 摘要字数 ≤ 300（CNIPA 硬限制）
- 权利要求项数（提示附加费）
- 附图标记双向一致：说明书里的 100–111 与五幅图完全对应，任一侧的孤儿都报错
- 五份递交件的页面尺寸、页眉、页码、正文留白、字体和行距由 `tex/verify_layout.py` 实测
- 源文件与 PDF 的 SHA-256 清单写入 `output/CNIPA/build-manifest.json`

## CNIPA 形式要求对照表

依据《专利审查指南》第一部分第一章（申请文件的形式审查）与第二部分第二章（说明书和权利要求书）。每次编译时 `build.cjs` 会复验带 ✓ 的可自动检查项。

| 要求（出处） | 规定 | 本申请 |
|---|---|---|
| 纸张 | A4 210×297mm，单面纵向 | ✓ 递交件与工作文档均 A4 |
| 页边距 | 左、上各 25mm；右、下各 15mm | ✓ |
| 字体字号 | 宋体/仿宋/楷体，黑色，纸件字高**不低于 3.5mm** | ✓ 正文宋体 12bp，字框 4.23mm |
| 行距 | **2.5–3.5mm** | ✓ 实测 3.00mm（基线距 7.23 − 字框 4.23） |
| 页码 | 阿拉伯数字顺序编号，**置于每页下部页边的上沿，左右居中**；各文件分别编号 | ✓ 各文件从 1 起，页码下沿距纸边 ≥15mm |
| 排列顺序 | 请求书→摘要→摘要附图→权利要求书→说明书→说明书附图 | ✓ 见上表 |
| 发明名称 | 一般不超过 25 字，不得含人名地名商标型号 | ✓ 22 字 |
| 说明书首行（4.2） | **第一页第一行正文写明发明名称并左右居中**，名称前不得冠以任何字样，名称与正文间空一行 | ✓ 页眉为“说明书”，正文首行是发明名称 |
| 说明书结构（4.2） | 技术领域/背景技术/发明内容/附图说明/具体实施方式，各部分前写明标题 | ✓ 五部分齐全 |
| 说明书插图（4.2） | 文字部分可有数学式、表格，**不得有插图** | ✓ 无 |
| 禁用引用语（2.2） | 不得使用「如权利要求……所述的……」 | ✓ 全文无 |
| 权利要求编号（4.4） | 阿拉伯数字顺序编号，**编号前不得冠以「权利要求」「权项」** | ✓ 写作「1.」「2.」…… |
| 权利要求插图（4.4） | 不得有插图 | ✓ 无 |
| 摘要字数（4.5.1） | 文字部分含标点**不超过 300 字**，不得使用标题与宣传用语 | ✓ 299 字 |
| 摘要内容（4.5.1） | 须写明**名称、技术领域、技术问题、方案要点、主要用途**五项 | ✓ 五项齐全 |
| 摘要附图（4.5.2） | 指定说明书附图之一，在请求书中写明图号 | ✓ 指定图 1 |
| 附图绘制（4.3） | 计算机绘制，线条均匀清晰，黑色，**图周不得有与图无关的框线** | ✓ |
| 附图编号（4.3） | 两幅以上顺序编号并冠以「图」字，**标注在相应附图正下方** | ✓ 图 1～图 5 |
| 附图标记（4.3） | 阿拉伯数字；**说明书未提及的标记不得出现在图中，图中未出现的不得在说明书提及** | ✓ 100–111 双向一致（自动检查） |
| 附图文字（4.3） | 除必需词语外不得含注释；**流程图、框图应在框内给出必要的文字和符号** | ✓ 结构图只标标记，流程图/框图内有必要文字 |
| 附图缩放（4.3） | 缩小到 2/3 仍能分辨细节 | ✓ 图内正文 10.5pt，2/3 后约 7pt |

**已知待核实项**：审查指南 2.2.3 建议背景技术尽可能引证相关文件。本申请背景技术暂未写入未经独立复核的文献号；清单见「现有技术检索记录」，请代理人核实后决定是否补入。2026 年电子申请的 XML 转换和实质性专利审查不由 LaTeX 版式检查代替。

## 五个已验证的实现约束

**一、缺字是静默的，必须当构建失败处理。**

xelatex 遇到当前字体没有的字符时，PDF 里那个字**直接消失**，只在 `.log` 留一行 `Missing character: There is no ∧`，页面看上去毫无异常。专利文件里丢一个 `≥` 或 `∧` 会改变技术方案的含义。`symbols.sty` 把这类符号映射到 LaTeX 构造（源文件里仍然直接写 `∧ ≥ ①`，可读可编辑），`build.cjs` 则把 log 里的 Missing character 当作不通过。首次搬到 LaTeX 时，三份工作文档共丢了 12 个字符（`∧ ≥ ≤ ① ② ③`），全靠这条查出来。

**二、`\setCJKmainfont` 是 preamble-only 的。**

想在正文宏里切加粗宋体会报 `Can be used only in preamble`。正确写法是在导言区声明字族：`\newCJKfontfamily\cnbf{SimSun}[AutoFakeBold=3]`，正文里用 `{\cnbf …}`。字距用 ctex 的 `\ziju`。

**三、`-output-directory` 会把该目录也加进输入搜索路径。**

`.build/` 里若留着同名 `.tex`，xelatex 会优先读它而不是你刚改的那份，症状是"改了没反应"。中间文件用完即清。

**四、`\nopagebreak` 挡不住孤标题。**

它只是个惩罚值；标题正好排在版心最后一行时照样断开，正文被甩到下一页。硬约束是标题前加 `\needspace{4\baselineskip}`——剩余高度不够四行就把分页点提到标题之前。`cnipa.sty` 的 `\cn@keep` 就是干这个的，`build.cjs` 另有一道复查（把 `\cn@keep` 临时改成 `\relax` 可以验证闸门确实会报错）。`pdftotext` 取中文时**必须带 `-enc UTF-8`**，否则整段中文被丢掉只剩 ASCII，检查会假阴性通过。

**五、图内必须压回单倍行距。**

说明书正文采用固定 20.5bp 基线距；若直接让 TikZ 继承正文行距，多行节点会把流程图撑高。`patfig.sty` 的 `pfont` 样式统一压到 1.05。另外 TikZ 的菱形要把文字框整个装进去，宽度约为文字宽的两倍——菱形里的文字必须窄，宁可折两三行，也不要写成一长行把菱形撑到出血。

## 附图的合规要求

CNIPA 要求附图用黑色线条绘制，不着色、不加阴影，除必需的词语外不加注释。因此：

- 结构图（图 1）与桥接示意（图 4 下半）的模块内**只写附图标记**，模块名称在说明书的「附图说明」一节里解释；
- 流程图（图 2、3、5 和图 4 上半）内的步骤文字属于「必需的词语」，可以保留；
- 图 1 有且仅有一处连线交叉（107→101 的竖段与 108→104 的横段），是布局结构决定的，按普通交叉绘制，不加跨线弧。

改图之后 `build.cjs` 会自动核对附图标记与说明书是否双向一致。
