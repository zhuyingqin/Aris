# 软著申请表逐字段规则与坑

适用系统：中国版权保护中心「软件著作权登记系统」(register.ccopyright.com.cn)

---

## 一、字数限制：方向不一致，必须逐项确认

这是最容易翻车的地方。**同一张表里，有的字段是上限，有的是下限。**

| 字段 | 常见限制 | 方向 |
|---|---|---|
| 软件全称、简称、版本号、各类环境字段 | 50 字 | **上限** |
| 开发目的、面向领域 | 50 字 | 口径不明 |
| 软件的主要功能 | 500 字 | **下限**（不少于） |
| 技术特点 | 100 字 | **上限**（以内） |

### 应对策略

1. **不要假设「限 N 字」是上限。**中文里「限 500 字」既可能是不超过、也可能是不少于。软著申请表的「主要功能」栏通行要求是**不少于 500 字**，与直觉相反。
2. **口径不明的字段，压到正好等于限值。**例如开发目的说「限 50」但不确定方向，就写成正好 50 字——上限解读和下限解读同时满足，不必先去确认系统怎么校验。
3. **主要功能与技术特点在系统上是两个独立输入框**，不要合并撰写。
4. 用 `scripts/check-fields.cjs` 逐项校验，不要靠肉眼数中文字数。
5. 字数按「去除空白字符后的字符数」计。

### 被压缩掉的内容不要丢

申请表字段短，说明书不限。把完整描述放进说明书对应章节，申请表只留摘要，并在模板里注明对应关系（例如「完整的开发背景见说明书第 1.2 节」）。两边不矛盾，审查员要细节时看说明书。

## 二、软件名称

**硬规则**

- 必须有中文全称，**不接受纯外文名称**
- 名称中**不得含版本号**（版本号是独立字段）
- 不得含「中国」「中华」「国家」「国际」等字样
- 不得含绝对化宣传用语（「最」「第一」「领先」）
- 建议以「软件」「系统」「平台」结尾
- **可以含企业字号**，且很常见

**两条非显然的**

- **简称允许为纯外文。**纯外文的限制只针对全称。
- **强烈建议登记成「中文名（English Name）」中英并列形式。**理由：软件界面标题、安装包名往往是英文，说明书截图会显示英文名；若登记名是纯中文，审查员可能因「截图与登记名称不符」要求补正。括号内附英文可一次性规避。

**版本号**

格式 `V` + 数字。首次登记若写 `V0.x.y`，审查员可能质疑「尚未完成开发」。惯例是首次登记直接写 `V1.0`，即使代码仓库里是 0.x。

## 三、日期与发表状态

- **开发完成日期**必须早于或等于首次发表日期。
- **代码公开在 GitHub 并打了 Release，在著作权法上属于已发表。**填「未发表」与事实不符，且发表日期决定保护期起算。
- 查首个 Release 日期：

```bash
git log --tags --simplify-by-decoration --format="%ad %d" --date=short | tail -5
```

## 四、著作权人：个人 vs 公司

选公司会连带改变三项，且引出一个权属问题。

| 项 | 个人 | 法人（公司） |
|---|---|---|
| 证件类型 | 居民身份证 | 统一社会信用代码证 |
| 证明文件 | 身份证正反面 | 营业执照副本复印件，**加盖公章** |
| 权利取得 | 原始取得 | 原始取得，情形为**法人作品或职务作品** |

**⚠️ 著作权人名称必须与证件逐字一致。**公司名要含行政区划前缀和「有限公司」等组织形式后缀，写字号简称会被直接退回。

**⚠️ 公司登记时检查代码仓库的署名。**若 LICENSE 署的是个人名（常见于开源项目），而登记主体是公司，构成对外可见的权属矛盾。审查员看不到 LICENSE，不影响本次登记，但应处理：

1. 把 LICENSE 版权行改为公司全称
2. 补《著作权归属确认书》或在劳动合同中明确职务作品条款
3. 若代码已按开源协议发布，**已发布版本的授权无法撤回**——公司若要主张独占或对外授权收费，需先评估

## 五、开发方式

「独立开发」= 由本著作权人一家独立完成，未与外单位合作、未接受外部委托。若实际有合作单位或是受客户委托，必须改选并附相应协议。**这一项填错属于登记不实。**

---

## 六、「原创」勾选是法律声明

勾「原创」意味着声明提交的源程序均为自主开发。提交前必须排查：

| 风险点 | 处理 |
|---|---|
| 嵌入或补丁化的第三方项目 | 相关文件整个排除，不计入源程序量 |
| 复用第三方 UI 的样式类名 | 排除该部分样式文件；通常整体排除 CSS 最省事 |
| 打包分发的第三方二进制 | 属捆绑分发，非本软件源码，不申报 |
| 依赖包与构建产物目录 | 排除 |

源程序量应只统计自研源文件。`gen-source-listing.cjs` 的 `thirdPartyTokens` 就是为此设计：**文件内容命中任一关键词即整个文件排除**。

## 七、附件材料规格

### 源程序

- 每页**不少于** 50 行，共 60 页
- 取**前 30 页 + 后 30 页**，中间省略并加省略声明
- 每页页眉标注软件全称与版本号，页脚标注**连续页码**
- **不得用空行填充**
- 不足 60 页则全部提交

### 软件说明书

- 同为 60 页，前 30 + 后 30；不足则全部提交
- 内容：安装说明、运行环境、各模块操作步骤、主要功能
- 截图中的软件名称必须与登记全称对得上
- **纯文字无截图也合规**，但有截图更不容易被要求补正
