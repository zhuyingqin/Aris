# SomniQ Studio

### 面向完整科研过程的本地优先自主研究工作台

**让 AI 不只是回答一个问题，而是持续推进一个研究项目。**

</div>

## SomniQ Studio 是什么

SomniQ Studio 是一个以桌面端为核心的自主研究工作空间。它把研究问题、项目目标、文献、实验、证据、代码、写作和审查组织在同一个持续上下文中，让研究从一个想法逐步收敛为可验证、可追溯的成果。

它不是一个换了界面的聊天机器人，也不是以“生成代码”为终点的编程助手。SomniQ Studio 面向的是研究本身：

- **研究目标是长期状态**：使命、当前里程碑和历史决策不会随着一次对话结束而消失。
- **证据是核心产物**：文献、数据、实验结果、代码和论文内容共同构成可以检查的证据链。
- **审查是默认流程**：Executor 负责推进工作，Independent Reviewer 从独立角色出发质疑方法、证据和论证。
- **修订形成闭环**：审查意见会回到执行阶段，直到达到明确的质量标准，而不是在第一版答案处停止。
- **研究者保留方向权**：AI 推进过程，研究者决定问题、边界、关键判断和最终接受标准。

## 一个持续运行的科研系统

![SomniQ Studio 自主科研工作台](figures/somniq-studio-autonomous-research.png)

SomniQ Studio 的基本工作单元不是一条提示词，也不是一次代码提交，而是一个带有目标、证据、审查和历史的研究项目。每一轮执行都产生研究产物，每一轮审查都形成可执行的修订意见；通过质量门后，结果才成为项目中可追溯的结论。

## 相较 Claude Code 和 Codex 的优势

[Claude Code](https://www.anthropic.com/product/claude-code) 是以代码库和软件交付为中心的 agentic coding system；[Codex](https://openai.com/codex/) 同样起步于编码代理，并在向更广泛的知识工作扩展。它们都是优秀的通用执行系统。SomniQ Studio 的优势并不是简单地“更会写代码”，而是把代理能力放进了一个为科研设计的长期系统。

| 对比维度 | Claude Code / Codex | SomniQ Studio |
| --- | --- | --- |
| 产品中心 | 通用代理执行，尤其是代码库与工程任务 | 研究问题与科研项目 |
| 基本工作单元 | 会话、任务、代码变更或并行代理工作 | 使命、里程碑、证据和研究产物组成的持续项目 |
| 默认代理关系 | 由用户指挥代理执行任务，可扩展并行或审查流程 | Executor 与 Independent Reviewer 职责分离，审查—修订是默认闭环 |
| 完成标准 | 任务完成、结果验证并交付 | 结论有证据支撑，并通过方法、证据和论证的质量门 |
| 上下文组织 | 以代码仓库和当前任务为主要上下文 | 同时保存研究使命、当前目标、详细历史、证据与产物之间的关系 |
| 工作空间 | 围绕终端、IDE、代码仓库和通用代理任务组织 | 围绕文献、PDF、实验、数据分析、代码、LaTeX 和研究流程组织 |
| 自主推进 | 长时间或后台完成工程任务 | 围绕研究里程碑持续推进，并把每次执行和审查沉淀回项目状态 |
| 可审查性 | 展示代码差异、命令结果和测试证据 | 除执行记录外，还强调研究主张、来源、实验结果和审稿意见之间的证据链 |

### 1. 从“完成任务”升级为“推进研究”

Coding agent 通常从一个明确的工程任务开始，并以代码结果结束。SomniQ Studio 关心任务在整个研究中的位置：它为什么要做、支持哪一项主张、产生了什么证据、下一步应当验证什么。代码是研究手段之一，而不是最终目的。

### 2. 独立审查不是一句提示词

让同一个代理“再检查一遍”容易延续原有假设。SomniQ Studio 将 Executor 和 Independent Reviewer 作为不同职责：前者构建答案，后者主动寻找薄弱证据、方法缺陷和论证跳跃。角色分离让批评成为系统结构，而不是偶尔发生的自我反思。

### 3. 研究上下文不会被压缩成聊天记录

长周期研究需要区分稳定使命、当前里程碑、详细历史和已经确认的证据。SomniQ Studio 把这些内容作为项目状态保存，使新的会话和新的研究阶段能够继承真正重要的上下文，而不是依赖研究者反复复述背景。

### 4. 结果不仅要生成，还要能够追溯

一段流畅的文字并不等于可靠结论。SomniQ Studio 将文献来源、实验过程、结果、研究主张和审查意见放在同一条证据链上，使成果能够被复核、修订和继续发展。

### 5. 一个面向科研对象的桌面工作台

SomniQ Studio 把聊天、文献阅读、实验环境、数据与代码、LaTeX 写作、PDF 预览、研究工作流和运行状态放进同一个产品表面。研究者看到的不是一组彼此割裂的代理任务，而是一个正在持续演化的研究项目。

## SomniQ Studio 的核心判断

> 真正困难的不是让 AI 写出更多内容，而是让研究在长期运行中仍然保持目标、证据、批判性和连续性。

Claude Code 和 Codex 把 agentic workflow 带入软件工程；SomniQ Studio 要做的是把同样强大的执行能力，组织成一套可以持续推进、独立审查并沉淀证据的科研工作系统。
