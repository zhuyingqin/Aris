## 2. 目标架构

| 环节 | 设计与理由 |
|---|---|
| 写入 | Runtime 在回合落盘后增量索引。用户可显式固定长期项，Executor 仅在出现明确纠正、可复用发现或有验证的修复时写带出处的 L1 笔记。工具失败与恢复由 runtime 记录同一目标、错误签名及验证结果。这样普通回合零额外模型调用，笔记也有证据可查。 |
| 存储 | Session JSONL 是原始证据。少量 L1 笔记按项目追加，来源由 runtime 绑定到消息或工具调用。SQLite 只作可重建索引，常驻继续用现有 Markdown，旧 v2 冻结归档。这样能纠错和重建，也避免维护两套历史库。 |
| 检索 | 扩展 `session_search`，先按项目、时间和条目状态过滤。FTS5 用 BM25 分别排中文字符二元组与英文、路径、错误码，再用 RRF 合并。工具日志单列、限长，默认返回少量片段和原文锚点。现有含中文查询直接走 `LIKE`，混合索引能让罕见术语和错误码参与排序。[session_index.rs](F:/Agent/Aris-memory-exp/crates/runtime/src/session_index.rs:997) |
| 送达 | system 的记忆部分只放用户确认的常驻项，按版本更新。其余由模型调用工具，或在用户明确引用历史、同目标重复失败时自动调用一次，以有界的工具结果送达。这样既保住稳定前缀，也照顾模型忘记查历史的情况。 |
| 整理 | 按来源和规范化内容去重，以原始时间判失效，已生效的更正才替换旧项，保留旧版本。跨会话复用只提高候选优先级。机器提案由独立 Reviewer 核验证据和冲突，用户确认适用范围后才晋升。这样保留独立审查，也把长期意图的决定权留给用户。 |

L1 设计稿值得采纳的是来源绑定和修正记录。首版省掉定时补录与近期笔记注入，L2/L3 晋升也省掉高置信直写。

## 3. 可证伪的离线假设

按项目和时间前推回放，查询只看当时可见的内容。人工标注重学回合的最小证据跨度、是否明确长期授权和少量普通负例。用早期会话调参，后期会话验收。以下是预设门槛，尚未跑回放。样本不足时报告分母，暂不下结论。

| 假设 | A / B | 指标与 B 的判定线 |
|---|---|---|
| 1. 确认门能阻止临时决定常驻 | 日志中实际送达的 v2 决定与约束 / 同一批只准入当时已有明确长期授权的条目 | 无长期授权项占比 ≤5%，已明确授权项保留率 ≥95% |
| 2. 混合 BM25 能找准中文证据 | 现有 `session_search` / 同语料和预算下的二元组＋英文 BM25 融合 | 中文或混合查询的证据 Recall@5 提升 ≥10 个百分点 |
| 3. 只查近期会漏掉关键历史 | 同一检索器只查前 48 小时 / 查全部先前历史 | 跨会话重学的证据 Recall@5 提升 ≥20 个百分点 |
| 4. 稀疏触发能替代大部分逐轮送达 | 每轮搜索 / 仅按历史指代或同目标重复失败触发，两者用同一检索器 | B 的证据送达率达到 A 的 ≥85%，普通回合触发率 ≤10% |
| 5. 工具结果能保住更多前缀 | 同一批回放请求把相同片段放在 system 末段 / 放在历史之后的工具结果中 | 未压缩且配置不变的相邻请求，共享前缀覆盖历史 token 的中位数提升 ≥30 个百分点。此项只测缓存代理指标 |
| 6. 同工具成功经常被误认作修复 | 同工具后续成功 / 同目标成功且日志有结果验证 | 人工标注的修复精确率提升 ≥15 个百分点，已验证修复保留率 ≥80% |
| 7. 显式替换能压低过时命中 | 只靠 TTL 和时间排序 / 增加按当时已生效更正做版本过滤 | 有明确更正的当前状态查询，Top-3 过时命中率至少减半，当前证据 Recall@3 下降 ≤5 个百分点 |

## 4. 明确不建议做的三件事

1. 批量回填旧会话生成原子库。可先重建原文索引，保留历史时间。
2. 用模型置信度、重复出现或长时间未反驳，自动把推断升级成用户规则。
3. 首版部署向量服务或训练晋升模型。先看词法基线剩下多少同义改写漏召回，再决定是否用 3060 跑本地向量对照。

## 5. 如果只能做一件事

**把跨会话历史召回迁到一个可回放的项目内 `session_search` 入口。** 先用带原文锚点的中文 BM25 跑通检索与触发验收，再通过开关撤掉逐轮动态注入。这条路径直接服务现有历史，也能在引入任何新写入管线前测清连续性收益。
