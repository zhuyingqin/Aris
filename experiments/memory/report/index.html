结论：选哪个方向

双通道记忆，系统负责送达，不进 system prompt。“前情回顾”用原始会话检索（不抽取），“踩坑重现”用短教训笔记 + 报错触发；v2 后台抽取撤掉；每轮 system 注入先做对照再撤。常驻的 MEMORY.md / USER.md 只收用户确认的条目——这一条本次没有做实验，依据是 10 月的诊断（30% 自动“决定”是误判）。

  1. 第 1 步：session_search 的中文路径从 LIKE 计数换成二元组 BM25（消息级）+ 近因加权；离线前情找回率 51% → 70%（同为工具检索）。同时开一个对照开关：每轮 system 召回块 开/关，量回答质量与缓存 token。
  2. 第 2 步：报错触发召回——工具失败时用报错文本查“教训”类笔记（跨项目），结果附在工具结果后。踩坑 4% → 69%。
  3. 第 3 步：教训笔记的写入（v7 补录：约每 7 回合 1 次廉价模型调用，只写“踩坑→修法”）。
  4. 第 4 步（需验证）：前情回顾的主动送达——每轮检索、只在高置信时把 1–2 个片段附在用户消息后。缺一个可靠的“何时不送”门槛：需要专用重排模型，再做一次端到端（回答是否变好）试验。
  5. 第 5 步：本地向量 / 重排模型（下载与打包决策），以及 L2/L3 晋升（只由用户确认）。

独立审查（Codex）指出的问题与处理

  • 前情回顾原先检索全部历史 → 已改为“在下一个会话开始时提问”，只看此前的会话。改后近因衰减从“更差”翻成“更好”。
  • 现状复刻漏了生产的前后 5 条消息窗口、v2 的中文分词把标点粘进词、没按更新时间取前 100、没过滤过期 → 已修，现状前情从 27% 变为 49%。
  • 踩坑 69% 没乘触发门 → 已乘（本批事件全部过门，数字不变）。缓存卡片原先跨了间隔档 → 改为同档比较。“零风险”等说法已删。
  • 未处理、只能注明：笔记按教训 ID 判分、原文按标注回合判分，口径不同；普通回合没有标注是否需要历史；全库 BM25 统计量含未来文档；现状按整组任意命中计（偏宽松）。审查原文见 agents/outputs/codex_review.md。

看结果时要知道的

  • 单用户、单机器；测试集只有 52 / 59 道题，±10 个百分点以内的差别不要当真。开发集只用来挑配置。
  • 前情回顾的考题由独立的 Claude 子 agent 从真实回合改写（问题与原文的二元组重合中位 26%），可能仍偏向词法检索。
  • 这里量的是“找没找到”，不是“回答有没有变好”；端到端效果另需付费试验（审查建议的下一步：按事件时间滚动回放 + 盲评送达文本能否回答或修复；以及现状注入与双通道送达的随机配对对照）。
  • 缓存对比的新回合样本只有 29 个请求，且受服务商缓存过期影响（>5 分钟两组都≈0）。
  • v7 笔记的召回规则曾在开发集上迭代过 7 轮；本页用的是统一的 BM25，未用当时调过的指纹规则。
  • 通用 Qwen3-0.6B 不是重排专用模型；向量与专用重排两个节点待下载模型后补测。
